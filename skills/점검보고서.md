# 스킬 점검 보고서 (2026-09-29)

직접 만드신 스킬 18개를 점검했어요(`media-use`는 외부 설치 패키지라 제외, 기본 제공 스킬도 제외).

## 핵심 발견 — 왜 스킬 내용 일부를 놓쳤나

1. **비슷한 스킬끼리 규칙이 서로 반대였음** — `daechi-snt-payment-summary`는 "할인 기본 없음", `daechi-snt-tuition-invoice`는 "할인을 먼저 물어봄". 둘 다 "학부모 결제 금액"이라 섞여 불리면 한쪽 규칙을 놓침 → **하나로 합치고 맨 앞에서 모드(A 카톡 결제내역 / B 수강료 정리표)부터 정하게** 함.
2. **과거 이력이 현재 규칙을 가림** — `don5060-longform`은 맨 위에 긴 "변경 이력", 본문 곳곳에 "9/28에 이렇게 했었다"가 섞여 있었음 → 현재 규칙을 앞에, "결정 배경"은 맨 아래로.
3. **"머릿속에서 바꿔 읽어라" 지시** — `longform-video-design`이 영어 + 옛 도구(HyperFrames) 기준이라 "Remotion으로 치환해서 읽어라"고 되어 있었음 → 한국어 + Remotion 용어로 바로 읽히게.
4. **없는 스킬을 가리킴** — `remotion`, `don5060-longform`이 **꺼져 있는 `donui-gwejeok-video`**를 필수처럼 참조 → 꺼져 있을 때의 대안(저장소)을 명시.
5. **이름과 주소가 다른 링크** — `daechi-snt-tasks`가 이름은 "학사 운영 허브", 주소는 "학원 운영 본부"(3층)를 적어둠 → 비상 경로를 3층(학원 운영 본부) → 🏫 학원 업무 목차 순서로 통일.
6. **같은 값이 여러 곳에** — 정산 선생님 명단이 3곳에 중복 → `teacher_policy.md` 하나만 기준으로.
7. **스킬끼리 모순** — `sns-upload` "블로그 1,500자 내외" vs `naver-blog-post` "1,500자는 공식 기준 아님, 늘리지 말 것" → 통일.
8. **문서에 없는 기능** — `tuition-schedule`의 `build_temp_saturday.py`(토요일 임시 강의실), 데이터 항목 `clinic_union`·`note` 설명 추가.

## 모든 스킬에 적용한 공통 구조
`0. 시작 전 반드시 확인(놓치기 쉬운 것 먼저)` → `작업 순서` → `세부 규칙` → `전달 전 점검` → `다른 스킬과의 경계` → `⚠ 과거 실수(한 줄씩)` → `결정 배경`. 중요한 규칙이 맨 앞과 맨 끝에 오도록. 이 구조는 `save-as-skill`에도 넣어서 앞으로 스킬을 고칠 때도 유지되게 함.

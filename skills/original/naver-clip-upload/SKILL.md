# 네이버 클립 업로드 자동화 (돈5060)

이미 만든 쇼츠 mp4를 네이버 클립에 올린다. 쇼핑 스티커(도서)와 블로그 글을 걸어 수익·트래픽으로 연결하는 게 목적이다.

프로젝트 루트: `C:\Users\koyon\클로드\Claude코드\코딩프로젝트\돈5060-유튜브팀`
클립 크리에이터: `https://clipcreators.naver.com` (블로그와 같은 네이버 로그인 세션)

## 고정 값

| 항목 | 값 |
|---|---|
| 무엇을 올리나 | 배포 대기열 항목의 영상(유튜브에 공개된 것과 같은 영상) |
| 블로그 연결 | **그 영상으로 방금 발행한 새 블로그 글** — 목록에서 제목으로 찾는다 |

## 안전 규칙

- **등록 버튼은 사용자 확인 후에 누른다.** 설정을 다 채운 뒤 보여주고 확인받는다. 중간 저장은 `임시저장`.
- **하루에 실제 영상 1편만.** 테스트 업로드·더미 영상을 올리지 않는다.
- **오류가 나면 그 자리에서 멈추고** 화면 문구 원문과 어디까지 됐는지 알린다. 같은 클릭·업로드 재시도, 원인 진단 후 수정, 다른 선택자·경로로 우회 — 모두 사용자 지시 없이는 하지 않는다. 다시 하기 전에 `콘텐츠 > 동영상` 목록에 초안·예약이 이미 생겼는지 먼저 확인한다(중복 방지). (반복 시도는 봇으로 오인돼 계정이 제한될 수 있다.)
- 선택자를 알아내려고 실제 계정에서 반복 실험하지 않는다. 아래 검증된 선택자를 쓰고, 안 맞으면 스크린샷을 보며 한 단계씩.
- 로그인이 풀려 있으면 로그인 시도하지 말고 "로그인 필요"라고 보고한다(자격증명 입력 금지).
- 이미 등록된 클립은 수정·삭제하지 않는다. 예약 날짜 수정도 사용자가 직접 한다.
- 배포할 항목이 없으면 네이버에 접속하지 않는다.
- 이전 실행이 남긴 자동화 브라우저가 `.pw-profile`을 잡고 있으면 새 실행이 막힌다 — 명령줄에 `pw-profile`이 든 자동화용 `chrome.exe`만 종료한다(사용자의 일반 크롬은 건드리지 않는다).
- **브라우저 창은 닫지 않는다.**

## 0단계 — 세션

블로그 작업 직후면 같은 상주 REPL을 그대로 쓰고 `go("https://clipcreators.naver.com/web/dashboard")`로 이동한다. 새로 시작할 때는 `naver-blog-post` 스킬 0단계와 같은 방법(desktop-commander 상주 REPL, `python -X utf8 -i -u`)으로 `open_browser("https://clipcreators.naver.com/web/dashboard")`. desktop-commander가 없으면 조용히 방식을 바꾸지 말고 먼저 묻는다.

## 1단계 — 영상 확인

대기열 항목의 `영상:` 경로. 없으면 `output/`에서 찾고 애매하면 묻는다. 클립 한도는 최대 3분·8GB·세로형 권장 — 우리 쇼츠는 항상 통과.

설명을 쓰려면 내용을 알아야 한다: `metadata/<이름>_description.txt`와 방금 쓴 블로그 글을 근거로 쓴다. 사용자가 요약을 주면 그게 최우선. 둘 다 없으면 영상에서 2초 간격으로 프레임을 뽑아 자막을 읽되(`ffmpeg -vf fps=1/2`), 자막에서 확인되는 표현만 근거로 쓰고 `output/_frames/`는 지운다.

## 2단계 — 업로드 화면

```python
pp = g["_state"]["page"]
pp.get_by_role("button", name="업로드").first.click()
pp.get_by_text("동영상 업로드").first.click()
pp.query_selector("input[type=file]").set_input_files(<mp4 절대경로>)
```
파일을 넣으면 업로드가 시작되고 설정 폼이 바로 뜬다. 업로드·인코딩이 도는 동안 폼을 채운다.

## 3단계 — 설명 (300자, 채널 고정 템플릿)

```
[클립용 제목 — 상황이 드러나는 검색어]

결론부터 한 문장 + 요약 1~2문장(숫자·구체 표현).

타인에게 휘둘리지 않고 내 삶의 주인이 되는 법, 쇼펜하우어의 지혜를 통해 확인해 보세요.

📖 추천 도서는 영상 속 쇼핑 스티커를 클릭해 보세요!

#돈오공육공 #시니어처세술 #5060지혜 #인간관계정리 #쇼펜하우어 #마흔에읽는쇼펜하우어 #처세술 #<영상 전용 태그 3~5개>
```
- **문단 사이 빈 줄**을 반드시 넣는다(모바일에서 덩어리로 보인다).
- "📖 추천 도서는…" 줄은 빼지 않는다.
- 300자가 빠듯하면 요약부터 줄인다(고정 문구·고정 태그는 그대로).
- 1인칭으로 쓰지 않는다(3인칭 소개). 각색·AI 고지는 300자 제한 때문에 넣지 않는다 — 연결한 블로그 글에 있다.
- textarea를 클릭하고 줄마다 `insert_text` + `Enter`. 입력 뒤 카운터(`n/300`)와 해시태그 칩 인식을 확인.
- 영상 내용과 무관한 인기 태그는 넣지 않는다.

## 4단계 — 커버·카테고리·AI 활용

- **커버**: 커버 후보는 업로드 1~2분 뒤에 채워진다. 후보가 뜬 뒤 `input[type=file][accept*='image']`에 커버 이미지를 넣으면 맨 앞에 추가되며 선택된다 — 맨 앞 카드에 체크가 있는지 스크린샷으로 확인. 쓸 이미지가 없으면 네이버 자동 후보를 고르지 말고 사용자에게 묻는다.
- **카테고리**: `1차 카테고리` 버튼 → "인문, 교양" → `2차 카테고리` 버튼 → 나온 옵션 클릭. (드롭다운 아래 보이는 칩은 표시일 뿐 클릭해도 선택되지 않는다.)
- **AI 활용 설정**: `button[role=switch][aria-label="AI 활용 설정"]`의 `aria-checked`가 `true`가 되게.

## 5단계 — 쇼핑 스티커

```python
pp.get_by_role("button", name="쇼핑", exact=True).first.click()
pp.get_by_role("button", name="상품 정보").click()
pp.get_by_text("상품 ID", exact=True).first.click()
# 검색창 클릭 → 9973283901 입력 → Enter → 결과 1건의 "선택"
```
키워드 검색은 쓰지 않는다 — "마흔에 읽는 쇼펜하우어"는 0건, "쇼펜하우어"는 필사노트만 나온다. 정보 태그는 쇼핑 1개만 쓴다. 쇼핑 스티커는 네이버 쇼핑이라 쿠팡 고지가 필요 없다(설명에 쿠팡 링크를 따로 넣을 때만 설명 맨 앞에 고지).

## 6단계 — 블로그 글 연결

`pp.get_by_role("button", name="블로그", exact=True)` → 내 블로그 글 목록이 바로 뜬다 → **방금 발행한 글의 제목**을 찾아 그 카드의 `선택`. 콘텐츠 링크는 블로그·네이버TV·뉴스 중 하나만 가능.

## 7단계 — 재생목록

`button[class*="playlistBtn"]` → 목록에서 "손해없는 처세 관계" 체크 → `완료`. 확인: "재생목록 1"로 바뀌었는지. 주제에 맞는 목록이 없으면 **새로 만들지 말고 묻는다.** 팝업이 열려 있는 동안엔 뒤쪽 클릭이 막히니 닫고 진행한다.

## 8단계 — 예약 공개

- `label:has-text("등록 예약") input` → `.check()`
- 날짜: `button[class*="datePickerDateBtn"]` 클릭 → 달력에서 **내일** 클릭 → 달력 하단 **`저장`**까지 눌러야 반영된다. 날짜 버튼의 `inner_text`로 바뀌었는지 확인. 달력이 화면 아래서 잘리면 날짜 버튼이 화면 중간에 오게 스크롤한 뒤 연다.
- 시간: `button[aria-label="시간"]` → 목록 **위에서 마우스 휠**로 스크롤해 `08` 클릭. 분은 `00`. 확인: 두 버튼 텍스트가 `08`, `00`.

## 9단계 — 등록

등록 전 체크(스크롤하며 눈으로):
- [ ] 설명: 템플릿 + 문단 사이 빈 줄 + 해시태그 칩, 300자 이하
- [ ] 커버 선택됨
- [ ] 카테고리 1차·2차
- [ ] AI 활용 설정 켜짐
- [ ] 쇼핑 스티커 9973283901
- [ ] 블로그 글 연결
- [ ] 재생목록 추가됨
- [ ] 예약: 내일 08:00

사용자에게 보여주고 확인받은 뒤 `button[class*="submitBtn"]`. "등록 완료 / N월 N일 8시 0분에 동영상이 공개될 예정입니다" 팝업의 날짜·시각을 읽어 기록하고 `확인`으로 닫는다. 인코딩이 안 끝났어도 등록해도 된다(닫아도 계속 진행).

끝나면 `distribution_queue.md`의 클립 칸을 `[x]`로, 임시 파일(`output/_frames`, 스크린샷)은 지운다.

## 검증된 선택자

| 대상 | 선택자 |
|---|---|
| AI 활용 / 광고·협찬 / 전체 공개 토글 | `button[role=switch][aria-label="AI 활용 설정"]` 등 (`aria-checked`) |
| 등록 예약 | `label:has-text("등록 예약") input` |
| 예약 날짜 | `button[class*="datePickerDateBtn"]` → 날짜 → "저장" |
| 시간 / 분 | `button[aria-label="시간"]`, `button[aria-label="분"]` |
| 커버 | `input[type=file][accept*="image"]`, 후보 `button[class*="coverItem"]` |
| 카테고리 | 버튼 "1차 카테고리" / "2차 카테고리" |
| 정보 태그·콘텐츠 링크 | 버튼 "쇼핑", "블로그" (`exact=True`) |
| 재생목록 | `button[class*="playlistBtn"]` |
| 등록 / 임시저장 / 취소 | `button[class*="submitBtn"]` / `saveDraftBtn` / `cancelBtn` |

클래스 해시는 배포 때 바뀔 수 있어 `[class*="키워드"]` 부분일치로 쓴다.

## 노출·클릭 최적화

- 클립은 네이버 통합검색에도 노출된다. **설명 첫 줄(대괄호 제목)이 사실상 제목** — 상황이 드러나는 검색어를 넣는다.
- 해시태그는 최대 20개. 고정 7개 + 영상 전용 3~5개(대중·좁은 태그 섞기).
- **커버가 클릭을 결정한다** — 상황은 보여주되 결말은 감춘다. 커버 문구와 설명 첫 줄이 같은 말을 반복하지 않게.
- GEO: 요약은 결론부터 한 문장, 숫자·구체 표현.
- 하지 말 것: 조회수·좋아요 조작, 무관한 인기 태그, 낚시성 커버.
- 성과가 꺾이거나 3개월쯤 지났으면 `naver-blog-post` 스킬의 `references/growth-loop.md`를 읽고 이 섹션을 갱신한다. 웹의 통설보다 `분석` 탭의 우리 숫자를 우선한다.

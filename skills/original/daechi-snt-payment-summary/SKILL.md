# 학부모 결제 내역 카톡 정리

과목별 금액(과 필요시 회차)을 합산해서 학부모에게 카톡으로 바로 보낼 수 있는 결제 내역 문구를 만드는 스킬.
daechi-snt-tuition-invoice 스킬과는 다르다 — 그 스킬은 항상 할인 여부를 먼저 물어보고 회차 중심으로 정리하는
스킬이고, 이 스킬은 **기본이 할인 없는 합계**이며 결과물이 학부모에게 보내는 카톡 메시지 형태라는 점이 다르다.

## 전제

- 과목별 금액은 사용자가 대화로 알려주거나 캡처/문서로 보여준 값을 그대로 쓴다. 지어내거나 암산하지 않는다.
- **기본값은 할인 없음.** 사용자가 "할인해줘", "3과목 10% 할인해줘", "OO 할인 적용해줘" 처럼 명시적으로
  요청한 경우에만 할인을 적용한다. 요청이 없으면 원래 금액을 그대로 더한 합계를 최종 금액으로 쓴다.
- 할인을 적용할 때는 몇 %이고 어떤 과목에 적용되는지 사용자가 알려준 그대로 반영한다 — 일부 과목만 지정했으면
  그 과목만 할인하고 나머지는 원가로 더한다. 애매하면 지어내지 말고 사용자에게 확인한다.
- 사용자가 다른 옵션(오픈특가, 단독 가격 등)과 비교해달라고 하면, 어떤 금액끼리 비교해야 하는지(예: 해당
  과목의 할인 전 금액 vs 대체 옵션 금액, 또는 전체 할인 적용 총액 vs 대체 옵션으로 전환했을 때의
  총액) 헷갈릴 수 있으므로, 비교 대상이 명확하지 않으면 지어내지 말고 어느 금액끼리 비교하는건지 사용자에게
  확인한다.

## 이월/차감 항목 반영

- 전월 이월금, 네이버 리뷰 차감처럼 결제 금액에서 빼야 하는 항목이 대화나 캡처 자료에 있으면 찾아서 반드시
  정리에 포함한다 — 사용자가 다시 언급하지 않아도 이전에 확인된 값이 있으면 챙긴다.
- 이런 차감 항목이 여러 과목에 걸쳐 있으면(예: 국어 이월금, 과학 이월금 등) 각각 어떤 과목/사유의 차감인지
  명시해서 적는다 — 뭉뚱그려 하나의 숫자로 빼지 않는다.
- 차감할 항목이 전혀 없으면 이 부분은 생략하고 바로 합계가 최종 결제 금액이 된다.

## 회차 내역 반영 (노션 문서)

- 노션에 수강회차·금액이 정리된 문서 링크가 있으면 그 문서를 확인해서 각 과목의 실제 수업 날짜/총 회차
  (예: `10/7, 14, 21, 28 (총 4강)`)를 금액 옆에 같이 적어준다. 날짜는 문서에 있는 값을 그대로 쓰고 새로
  계산하지 않는다 (재계산이 필요하면 tuition-schedule 스킬의 gen_dates.py를 쓴다).
- 노션 링크가 없거나, 사용자가 "이번엔 회차는 안 넣어도 된다"고 하면 회차 없이 금액만으로 정리한다 — 매번
  회차를 억지로 채우지 않는다.

## 형식은 예시일 뿐, 답안이 아니다

아래 "출력 형식"의 예시와 규칙은 참고용 기본틀이지, 글자 그대로 베낌 베끼 야 하는 고정 양식이
아니다. 매번 해당 건의 과목 수·할인 여부·차감 항목·비교 필요성을 보고, **학부모가 가장 쉽게
이해하면서도 간결하고 가독성 있는 구성**이 무엇인지 매번 판단해서 유연하게 구성한다.

- **같은 숫자를 두 번 보여주지 않는다.** 예를 들어 `합계: 000원` / `10% 할인 합계: 000원`을
  따로 보여주고 바로 이어서 `■ 최종 결제 금액 = 000원 − 000원 = 000원`처럼 동일한 숫자를 반복
  노출하지 않는다 — 최종 결제 금액 줄의 계산식에 이미 그 숫자들이 들어가 있으면 위에 따로 합계/할인합계
  줄을 반복해서 적지 않고, 계산식 한 줄로 갈음한다.
- 차감이나 비교가 없으면 계산식도 생략하고 바로 금액만 보여줘도 된다 — 억지로 계산 과정을 느리지 않는다.
- 비교/참고 문단은 필요할 때만, 핵심 차액과 결론(어느 옵션이 얼마 더 저렴한지)만 간결하게 한 문장으로
  적는다 — 중간 계산 과정을 늘어놓아 길게 쓰지 않는다.
- 항목이 1~2개로 적을 때는 과목별 줄 + 곰바로 최종 금액로 끝내도 되고, 굴이 중간 합계 줄을 넣을 필요가
  없다.

## 출력 형식 (참고용 기본틀)

아래 예시를 참고한다 (실제 값은 매번 사용자가 알려준/문서에서 확인한 숫자로 채우고, 바로 위의 유연성
규칙에 따라 불필요한 줄은 생략한다):

```
어머님~ 결제 내역 정리해서 드립니다^^

국어 (전진선T): 290,000원 → 10% 할인 금액 261,000원
공수2 (유재필T): 437,500원 → 10% 할인 금액 393,800원
과학 (노현석T): 220,000원 → 10% 할인 금액 198,000원

여기에 9월달에 미적용됐던 3과목 10% 할인분(126,000원)을 이번에 차감하면

■ 최종 결제 금액
= 852,800원 − 126,000원 = 726,800원

* 과학 한 과목만 오픈기념 15만원으로 계산하는 것보다, 3과목 10% 할인 적용한 금액이 24,700원 더 저렴합니다.

아버님 번호로 결제링크는 준비되어 있는데, 10% 할인 최종 결제 금액인 726,800원으로 결제링크 보내드릴까요?
```

규칙 (가독성 — 위 예시처럼, 다만 "형식은 예시일 뿐" 원칙이 우선):

- 첫 줄은 항상 `어머님~ 결제 내역 정리해서 드립니다^^` (수신 대상이 아버님이면 `아버님~ 결제 내역...`으로),
  그 다음 빈 줄.
- 과목별 줄: `과목명 (선생님T): 원래금액원` — 할인이 있으면 같은 줄에 `→ N% 할인 금액 할인금액원`을
  이어 붙인다. 할인이 없으면 원래금액만 쓰고 화살표를 붙이지 않는다. 회차를 포함할 때는 금액 줄 바로
  아래에 `날짜, 날짜... (총 N강)` 줄을 추가한다. 과목이 여러 개면 반복하고, 과목 사이에는 줄바꿈만 하고
  빈 줄은 넣지 않는다.
- **중간 합계 줄(`합계:`, `N% 할인 합계:`)은 선택사항이다.** 최종 결제 금액 줄의 계산식에
  원래금액합계와 할인/차감액이 이미 들어가있다면 이 줄들을 따로 적지 않고 생략한다 — 같은 숫자를
  두 번 보여주지 않는다. 과목이 많거나 계산이 복잡해서 중간 합계가 있어야 프야 이해하기 쉽다면그때만 넣는다.
- 차감 항목(이월금, 네이버리뷰 등)이 있으면 과목 목록 다음에 빈 줄을 넣고 `여기에 <설명>(<금액>원)을
  이번에 차감하면` 처럼 자연스러운 문장으로 이어준다. 여러 개면 항목별로 이유를 구분해서 적는다.
- 항상 빈 줄 다음 `■ 최종 결제 금액` 줄, 그 다음 줄에 `= 계산식 = 최종금액원` (계산식에 원래금액/할인후금액과
  차감 금액을 다 보여줘서 어떻게 나온 숫자인지 한눈에 보이게 한다). 이 줄 하나가 상위 합계 줄들을 대체한다.
- 다른 할인/옵션과 비교해서 얼마나 유리한지 사용자가 요청했거나 참고가 될 상황이면, 최종 결제 금액 다음에
  빈 줄을 넣고 `* 참고로, ...` 또는 `* ...` 한 문장으로 핵심 차액만 간결하게 적는다 — 중간
  계산 과정을 늘어놓지 않는다. 필요 없으면 생략한다.
- 마지막은 항상 빈 줄 다음 결제링크 발송 여부를 묻는 문장으로 마무리한다 (예: `아버님 번호로 결제링크는
  준비되어 있는데, N% 할인 최종 결제 금액인 000,000원으로 결제링크 보내드릴까요?`) — 부모 호칭은 실제
  결제링크를 보낼 대상(아버님/어머님)에 맞춰 쓴다.
- 금액은 항상 천 단위 콤마로 표기.

## 검증

최종 문구를 주기 전에 합계, 할인 후 합계, 차감액, 최종 결제 금액 계산을 파이썬 등으로 재검산한다 — 학부모에게
바로 나가는 카톡이므로 금액이 틀리지 않도록 특히 조심한다.

# 돈5060 배포 전체 세트

영상 한 편이 거치는 전 과정이다. 각 플랫폼의 세부 절차는 개별 스킬에 있고, 이 스킬은 **순서·타이밍·분기·추적**을 맡는다.

프로젝트 루트: `C:\Users\koyon\클로드\Claude코드\코딩프로젝트\돈5060-유튜브팀`

## 현재 상태 (바뀌면 이 표만 고친다)

| 플랫폼 | 상태 |
|---|---|
| 유튜브 | **사용자가 Studio에서 직접 업로드·예약.** 에이전트는 업로드하지 않고 YouTube API도 호출하지 않는다(조회 포함). 사용자가 "API 다시 써도 돼", "자동 업로드 다시 켜줘"라고 할 때만 재개. |
| 네이버 블로그 | 운영 중 (`naver-blog-post`) |
| 네이버 클립 | 운영 중 (`naver-clip-upload`) |
| 인스타그램 | **중지.** 사용자가 "인스타 다시 해줘"라고 할 때만 재개하고, 그때 밀린 영상을 올릴지 먼저 묻는다. |
| 쓰레드 | **수동.** 계정이 두 번 정지돼 API를 호출하지 않는다. 캡션 문안만 만들어 준다. |

## 순서와 타이밍

```
[제작] 소재 → 대본 → 영상 → 썸네일·메타데이터
  → [1] 유튜브: 사용자가 Studio에서 비공개+예약 업로드
  → ...유튜브 공개일...
  → [2] 공개 다음 날: 네이버 블로그 발행 (본문 하단에 유튜브 링크)
  → [3] 같은 날: 네이버 클립 업로드 ([2]의 글 연결), 공개는 업로드 다음 날 08:00
  → [4] 인스타 (중지 중)  [5] 쓰레드 (수동)
```

- **블로그는 유튜브 공개 뒤에 쓴다** — 공개 전에는 유튜브 링크가 안 열려서 죽은 링크가 박힌다.
- **블로그가 클립보다 먼저** — 클립의 "콘텐츠 링크 > 블로그"에는 발행된 글만 뜬다.
- **한 번에 한 편씩**, 공개일이 가장 이른 항목부터 배포한다. 날짜별 계획은 `distribution_queue.md` 맨 위의 배포 일정 표를 따른다.

## 0단계 — 배포 대기열 확인 (항상 여기서 시작)

`distribution_queue.md`를 읽는다. 배포 일정 표에서 **배포일이 오늘이거나 지났는데 안 끝난 항목**이 오늘 할 일이다.

- 사용자가 유튜브에 직접 올린 영상은 사용자가 알려준 URL·공개일로 대기열 항목을 만든다.
- 플랫폼 하나를 끝낼 때마다 `[ ]`를 `[x]`로 바꾸고, 전부 끝나면 `## 완료`로 옮긴다. 중간에 멈춰도 상태가 남아 있어야 이어서 할 수 있다.
- 항목에 적힌 개별 지시(예: "블로그 새 글 쓰지 말고 기존 글 연결", "클립 이미 등록됨 — 생략")를 따른다.

## 1단계 — 영상 확인

- 대기열 항목의 `영상:` 경로에 mp4가 있는지 본다. 없으면 `output/`에서 맞는 파일을 찾고, 애매하면 사용자에게 묻는다.
- 파일이 끝내 없으면 블로그까지만 하고 클립은 "파일 필요"로 `[ ]` 유지, 사용자에게 알린다.
- 내용은 `scenes/<이름>.json`과 `metadata/<이름>_description.txt`로 파악한다. 없으면 사용자에게 한 줄로 묻는다.

## 2단계 — 블로그

기본은 **영상마다 새 글**이다. `naver-blog-post` 스킬로 쓰고, 발행은 사용자 확인 후 누른다.
- 블로그 글의 유튜브 링크는 대기열의 `유튜브:` 주소를 그대로 쓴다.
- 발행한 글의 **제목을 기록**해 둔다(클립에서 그 제목으로 찾는다).
- 같은 소재의 글이 이미 있으면 새로 쓰기 전에 알린다 — 네이버는 비슷한 글 반복 발행을 스팸으로 본다.
- 사용자가 다른 방식을 원하면: ① 기존 글에 연결(어느 글인지 받는다) ② 블로그 없이 진행(클립 블로그 링크 비움).

## 3단계 — 네이버 클립

`naver-clip-upload` 스킬을 따른다.
- 블로그 링크: 2단계에서 **방금 발행한 그 글**.
- 공개: **업로드한 날의 다음 날 08:00** 예약.
- AI 활용 토글 켜기, 재생목록 추가, 쇼핑 스티커(상품 ID `9973283901`)를 빠뜨리지 않는다.
- 블로그에서 띄운 Playwright 세션을 그대로 쓴다(`go("https://clipcreators.naver.com/web/dashboard")`).

## 4단계 — 인스타그램 (중지 중 — 재개 전에는 실행하지 않는다)

재개되면 `instagram-reels-upload` 스킬을 따른다. 요점: 1080×1920 변환 → 유튜브 썸네일과 같은 사진·디자인에 문구만 짧게 바꾼 커버 → `--dry-run`으로 확인 → 승인 후 `--publish` → 사용자에게 앱에서 AI 라벨 켜기 안내.

## 5단계 — 쓰레드 (수동)

Threads API를 호출하거나 토큰을 요청하지 않는다. 500자 이내 문안(훅 + 핵심 + 질문형 마무리)만 만들어 준다. 인스타 게시가 쓰레드로 자동 공유되지는 않는다(API 게시는 크로스포스팅 대상이 아님).

## 플랫폼별 텍스트는 각각 쓴다

같은 영상이라도 복사해 붙이지 않는다 — 네이버는 비슷한 내용 반복 발행을 스팸으로 본다.

| | 분량 | 성격 |
|---|---|---|
| 블로그 | 정해진 글자 수 없음 ("1,500자"는 네이버 공식 기준이 아님 — 숫자 맞추려 늘리지 않는다, `naver-blog-post` SEO·GEO) | 검색 유입. 그 글만의 실천 체크리스트 |
| 클립 설명 | 300자 제한 | 채널 고정 템플릿 + 쇼핑 스티커 안내 + 해시태그 |
| 인스타 캡션 | 첫 두 줄이 승부 | 훅 → 목록 → 해시태그 10~15개 |
| 쓰레드 | 500자 제한 | 훅 + 핵심 + 질문형 마무리 |

**모든 게시물은 1인칭으로 쓰지 않는다** — 사연은 3인칭으로 소개하고 독자에겐 2인칭으로 묻는다(가상의 이야기가 운영자 실화로 읽히지 않게).

## 쿠팡 파트너스 고지 — 링크가 걸리는 곳에만, 맨 앞에

```
이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.
```
- 블로그: 쿠팡 링크를 넣을 때만 본문 맨 앞
- 인스타·쓰레드: 책을 소개하며 프로필 링크로 유도할 때만 캡션 맨 앞
- 클립: 쇼핑 스티커는 네이버 쇼핑이라 해당 없음
- 링크가 없으면 넣지 않는다. 뒤쪽(더보기 이후)에 두면 표시하지 않은 것과 같다.

## 확인 지점 (마음대로 넘기지 않는다)

블로그 **발행**, 클립 **등록**, 인스타 **게시**는 각각 결과를 보여주고 확인받은 뒤 누른다. 사용자가 "알아서 다 해줘"라고 명시하면 묶어서 확인해도 된다.

## 오류가 나면 — 멈추고 묻는다

- 어느 플랫폼이든 오류가 나면 **그 자리에서 멈추고** 오류 문구 원문과 어디까지 됐는지를 알린다.
- 같은 동작을 다시 하거나, 원인을 스스로 진단해 고치거나, 다른 방법으로 우회하지 않는다 — 사용자 지시를 받은 뒤에 한다. (반복 시도는 계정 제한을 부를 수 있고, 재시도하면 중복 게시된다.)
- 다시 하기 전에는 이미 올라갔는지 먼저 확인한다(블로그 글 목록, 클립 목록의 초안·예약, 인스타 프로필) — 게시 호출은 오류가 나도 실제로는 올라갔을 수 있다.
- 필요한 도구(desktop-commander 등)가 연결되지 않아 원래 방식을 못 쓰면, 조용히 다른 방식으로 바꾸지 말고 먼저 알리고 묻는다.
- 이미 끝난 플랫폼은 그대로 두고 `distribution_queue.md`에 상태를 남긴다.

자주 막히는 지점: 네이버 로그인 만료 → 사용자가 직접 로그인(자격증명 입력 금지) / 인스타 토큰 만료(60일) → 사용자가 Meta 콘솔에서 재발급 / 클립 인코딩 지연 → 기다리지 말고 등록 진행.

## 마무리 보고

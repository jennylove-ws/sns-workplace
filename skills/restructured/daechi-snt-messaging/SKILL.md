# 대치SNT학원 운영 안내 문자 작성

실제로 써온 6가지 문자 양식(`references/templates.md`)을 기준으로 선생님·학부모·학생에게 보낼 문구를 만든다. **어투·구조는 원본 그대로**, 반명/요일/시간/회차/수강료/강의실 같은 **숫자·사실 데이터만 최신 값으로** 채운다.

## 0. 시작 전 반드시 확인 (놓치기 쉬운 것 먼저)

1. **Notion "💬 문자양식 라이브러리"를 먼저 연다(연동이 있으면 매번).** 정본은 그 페이지다 — 결제방법 블록, 문의 번호, 카카오 채널 링크는 자주 바뀐다. 주소와 찾는 법은 `references/templates.md` 맨 위.
2. **어떤 양식인지 정한다** (6종 중 하나 — 아래 2번 표). 애매하면 "어떤 용도의 문자인가요?"라고 먼저 묻는다.
3. **숫자를 절대 새로 계산하지 않는다.** tuition-schedule 스킬의 `data/classes.json`, `gen_dates.py` 결과, 강의실배정 문서에서 그대로 가져온다. 이번 학기 데이터가 아직 없으면 tuition-schedule로 회차·강의실을 먼저 확정하거나, 반별 정보를 사용자에게 묻는다.
4. **사람만 아는 정보는 지어내지 않는다** — 계좌번호, 미납 학생 이름/미납일자, 상담 요청 내용. 빈칸으로 두거나(예: "계좌 입금 : ") 먼저 확인한다.
5. **학원명 태그는 항상 "대치SNT"** (사용자가 다른 이름을 지시하지 않는 한).
6. 여러 건을 한 번에 요청받는 경우가 많다 → 3번 정리 규칙대로 출력한다.

## 1. 공통 헤더/톤
- **학부모·학생 대상**: "안녕하세요, [대치SNT] 학원입니다."로 시작.
- **재원생 대상 강의실 안내**: 맨 위에 "★★ 재원생 필독 ★★".
- **선생님 대상**: "안녕하세요 OOO 선생님," 또는 "선생님,"으로 시작, 끝까지 존댓말.
- 맺음말은 원본 톤 그대로: 강의실 안내 "꼭 확인하시어 수강에 차질 없길 바랍니다.", 미납 안내 "확인 후 납부 부탁드립니다" + "감사합니다 :)", 선생님 안내 "해당 강의실 사용해주시면 됩니다. 감사합니다!" 등.
- 반/수업 표기는 tuition-schedule과 동일: `[학년]_반명 (과목) (OOOT) – 요일/시간 [회당 단가 또는 1개월 정액]`, 날짜 줄 `- 8/2, 9, 16 (총 N강, 총액)`.

## 2. 양식 6종 (원문 전체는 `references/templates.md`)

| 양식 | 대상 | 데이터 출처 |
|---|---|---|
| 1. 회차확인 문자 | 선생님 | classes.json / gen_dates.py 결과 (그 선생님 담당 반 전체) |
| 2. 수강료 안내 문자 | 학부모·학생 | 위와 동일 + 결제방법/주의사항 공통 블록 |
| 3. 강의실 안내 문자 | 학생·학부모 (재원생) | classes.json + 강의실배정 문서 |
| 4. 강의실 확인 문자 | 선생님 | 강의실배정 문서 (해당 선생님 담당 반 전체를 한 메시지로) |
| 5. 미납 안내 문자 | 특정 학생 1인 | 사용자가 알려주는 미납 정보 (자동 산출 불가) |
| 6. 상담요청 문구 | 선생님 | 사용자가 알려주는 상황 (예시 톤만 참고, 내용은 매번 새로) |

양식에 없는 일회성 공지(직보 종료 후 교재 정리 안내 등)는 억지로 끼워맞추지 말고 요청 내용 그대로 정중한 톤으로 새로 쓴다.

## 3. 여러 건을 한 번에 요청받았을 때
- **선생님 강의실 확인 문자**(한 선생님이 여러 반): 선생님 한 명당 메시지 하나, 그 안에서 반을 줄바꿈으로 나열(templates.md 4번).
- **학생·학부모 강의실 안내 문자**(반마다 별도 발송): 반 하나당 메시지 하나. 여러 반/선생님이면 **반 사이 `----`, 선생님(발송 묶음) 사이 `====`**.
- 몇 건이든 각 메시지 위에 `① [고2]_유신/창현A (신영준T)` 식 라벨을 붙여 대상별로 바로 복사할 수 있게 한다.

## 4. 작업 순서
1. 양식과 대상을 확인한다.
2. Notion 문자양식 라이브러리에서 최신 공통 문구를 확인한다.
3. 반/회차/수강료/강의실 데이터를 classes.json이나 관련 문서에서 가져온다(없으면 tuition-schedule 먼저 또는 사용자 확인).
4. 계좌번호·미납정보·상담 내용은 사용자에게 확인한다.
5. templates.md 양식대로 쓰고, 3번 정리 규칙을 적용한다.
6. **전달 전 검산**: 반명·요일·시간·회차·금액이 원본 데이터와 일치하는지 대조한다.

## 다른 스킬과의 경계
- 신규 모집·설명회·입시결과 같은 **홍보성** 문자 → `daechi-snt-marketing` (단, 브랜드 태그·문의처 규칙은 이 스킬과 동일)
- 한 가정에 보내는 **카톡 결제 내역 / 학기 수강료 정리표** → `daechi-snt-payment-summary`
- 회차·강의실 숫자 자체 → `tuition-schedule`

# 학원 회차·수강료 계산 + 강의실/시간표 파이프라인 (Tuition Schedule)

반(반명, 선생님, 요일/시간, 단가)의 수업이 실제로 어느 날짜에 열리는지 계산하고, 회차 수에 따라 수강료를 산출해 문서로 정리한다. 이어서 강의실 배정 문서와 HTML용 시간표 산출물까지 만든다. 대치SNT 학원 썸머/프리썸머 스케줄 작업에서 반복하던 패턴을 일반화한 것.

## 요청 종류별 — 어디부터 볼까

| 요청 | 할 일 | 볼 섹션 |
|---|---|---|
| "9월 수강료", "이 반 몇 강이야?", "8월 따로 9월 따로" | `gen_dates.py`로 날짜·회차·금액 계산 | 1, 2 |
| 반별 개별 수정("이 반은 8월부터", "요일 바꿔서") | 그 반만 재계산해서 그 부분만 교체 | 2-5 |
| 강의실만 바뀜 | `classes.json` sessions만 고치고 스크립트 재실행 | 3, 4, 6 |
| HTML 시간표·엑셀만 손봄 | `classes.json` 고치고 2)·3)·4) 재실행 | 4, 6 |
| "강의실 배정 파일이 바뀌었어, 보고 다시 만들어줘" | 문서 전체 다시 읽고 반 하나하나 대조 | 7 |
| 새 학기 `classes.json` 처음부터 | 확정된 강의실 배정 문서를 괄호 규칙으로 옮김 | 3 |
| "이번 주 토요일만 강의실이 바뀌었어" | `classes.json`은 그대로, 1회성 HTML | 4 (`build_temp_saturday.py`) |
| 학부모 공개용 학년별 시간표 | `build_grade_view.py <학년>` | 5 |

## 1. 핵심 원칙 (항상)

1. **날짜 계산은 절대 암산하지 않는다.** 반드시 `scripts/gen_dates.py`로 날짜와 회차 수를 구한다. 요일·월 경계 계산은 손으로 하면 틀리기 쉽고, 회차가 틀리면 수강료 전체가 틀린다.
2. **기본 기간 = 달력 기준 1개월(1일~말일).** 기간을 말하지 않으면 해당 월 전체("9월 수강료" → 9/1~9/30).
3. **사용자가 기간을 지정하면 그대로 쓴다**(1개월이 아니어도). 예: "8/17부터 9월 말까지", "8월 15일부터 8월 수강료만", "8월 1일부터 한달, 9월 한달 따로". 이런 지시가 있을 때만 달력월 규칙을 벗어난다.
4. **과금 방식은 두 가지뿐 — 반드시 구분한다.**
   - **회당 수강료제(per-session)**: `[회당 00,000원]` → 회차 수 × 단가 = 총액 (`gen_dates.py --fee`로 전달).
   - **1개월 정액제(flat monthly)**: `[1개월 000,000원]` → **금액을 회차 수와 절대 곱하지 않는다.** 날짜만 다시 계산해 몇 회인지 보여주고 금액은 정액 그대로 (`--fee`를 주지 않는다).
   - 원문에 어느 쪽인지 없으면 사용자에게 묻거나, 기존 총액을 회차로 나눠 역산했다는 사실을 반드시 각주(※)로 밝힌다. 추측한 숫자를 확정 금액처럼 제시하지 않는다.
5. **빠진 정보는 만들어내지 않고 묻는다.**
6. ⚠ `data/classes.json`에는 **어느 학기 기준인지 표기가 없다**(스킬을 마지막으로 올린 시점의 데이터). 요청한 학기와 맞는지 의심되면 Notion "🏫 학원 운영 본부 (Claude 조직도)" → 팀 1 섹션의 최신 "수업 회차 & 수강료 (원본 문서)"와 대조하거나 사용자에게 확인한다.

## 2. 회차·수강료 계산 절차

### 2-1. 반 목록(마스터 데이터) 확보
대화 중 반 목록, 또는 기존 문서(`썸머_수업_회차_수강료.docx`, `강의실_배정.docx` 등)를 기준으로 한다. 반마다 필요한 정보:
- 학년/반명 (예: `[고2]_유신/창현A (미적1)`)
- 선생님
- 요일 패턴 (예: 화·목, 월(수)금, 토). 괄호 표기는 "주 대체 요일"이라는 뜻이고, 데이터상으로는 **괄호 요일 = 클리닉**(3번 데이터 모델 참고)이며, 회차 계산에서는 별다른 말이 없으면 **본 요일만** 쓰고 괄호 안 요일은 뺀다: "화(목)" → 화요일만, "월(수)금" → 월+금. 실제로 어느 주에 대체 요일을 썼는지 원본 회차 기록이 있으면 그걸 우선한다.
- 과금 방식과 단가/정액
- 과목/그룹 (수학/국어/영어/약술논술/과학 등 — 문서 섹션 구분용)

### 2-2. 기간 결정
- 기본은 달력월 전체. 범위·시작일·분리 요청("8월 따로 9월 따로")이 있으면 그대로.
- 반마다 기간이 다르면("이 두 반만 9월로", "이 반은 8/15부터") **반별로 따로** `gen_dates.py`를 호출한다(뭉뚱그리지 않는다).

### 2-3. `gen_dates.py`로 계산 (`scripts/gen_dates.py --help` 참고)
```bash
# 회당 수강료제, 기본 1개월
python3 scripts/gen_dates.py --month 2026-09 --weekdays tue,thu --fee 50000

# 회당 수강료제, 임의 기간
python3 scripts/gen_dates.py --start 2026-08-17 --end 2026-09-30 --weekdays sat --fee 62500

# 1개월 정액제 — --fee를 주지 않는다(곱하면 안 되므로), 날짜/회차만
python3 scripts/gen_dates.py --month 2026-09 --weekdays mon,wed,fri

# 한 반을 여러 구간으로 (8월 따로 / 9월 따로)
python3 scripts/gen_dates.py --weekdays sat --split 2026-08-15:2026-08-31 \
    --split 2026-09-01:2026-09-30 --fee 80000
```
- 요일 코드: `mon/tue/wed/thu/fri/sat/sun` 또는 `월/화/수/목/금/토/일`. 주 2회 이상이면 콤마로 한 번에(화·목 → `tue,thu`).
- **정액제인데 기간이 정확히 1개월이 아니면**(예: 8/17~9/30): 정액을 그대로 쓸 수 없으니, 별도 지시가 없으면 회차만 계산하고 `※ 정액제 - 기간이 1개월이 아니므로 금액 별도 확인 필요` 각주를 달아 총액을 확정하지 않는다. "1개월 정액으로, 9월만 계산"처럼 못박아 주면 그대로 따른다.

### 2-4. 결과 정리
과목(섹션) → 선생님(소제목) → 반(굵게, 요일/시간/단가) → 날짜 줄(회차/금액):
```
[고2]_유신/창현A (미적1) (신영준T) - 화(목) 18:00-22:00 / 토 9:00-13:00 [회당 62,500원]
- 9/1, 8, 15, 22, 29 (총 5강, 312,500원)
```
- 워드(.docx)로 달라고 하거나 .docx로 주고받던 맥락이면 **`docx` 스킬을 함께** 써서 파일을 만든다(새로 만들거나 기존 파일 편집). 섹션은 `[ 수학 ]`, `[ 국어 ]`, `[ 영어 ]`, 선생님 소제목은 `<선생님T>` 형식 유지. 가정/추정 항목은 눈에 띄게(예: 빨간 이탤릭 각주) 표시.
- 채팅으로 짧게 물은 질문("이 반 9월에 몇 번이야?")이면 파일 없이 바로 답한다.

### 2-5. 이후 수정 요청
"이 반은 8월부터", "이건 삭제", "요일 바꿔서" 같은 반별 수정이 매우 흔하다. **전체를 다시 만들지 말고** 해당 반만 `gen_dates.py`로 재계산해 그 부분만 갱신한다(docx는 `str_replace` 등으로 해당 블록만 교체).

## 3. 데이터 모델: `data/classes.json` (모든 산출물의 단일 소스)

스키마 예시는 `data/classes.schema_example.json`.
```json
{
  "teachers": {"T01": "맥심", "T08": "신영준"},
  "classes": [
    {
      "id": "C005",
      "name": "[고2] 유신/창현 A (미적1)",
      "teacher_id": "T08",
      "subject": "수학",
      "grade": "고2",
      "pricing": {"type": "per_session", "unit_fee": 62500, "count": 12, "total": 750000},
      "sessions": [
        {"day": "화", "start": "18:00", "end": "22:00", "room": "6강의실"},
        {"day": "토", "start": "09:00", "end": "13:00", "room": "6강의실"},
        {"day": "목", "start": "18:00", "end": "22:00", "room": "1강의실", "clinic": true}
      ]
    }
  ]
}
```
- `pricing.type`: `per_session`(단가×횟수) 또는 `flat_monthly`(정액, 절대 곱하지 않음).
- `sessions[].clinic: true` — **원문에서 요일이나 시간이 괄호로 표시된 것은 전부 클리닉.** 예: "화(목)"의 (목), "월(수)금"의 (수), "(화)(목)=9강의실", "(클리닉)=5강의실", "정규(13:00-14:30)=9강의실 / 클리닉(14:30-15:30)=7강의실". 괄호 없는 "화", "월·금"은 정규.
- `sessions[].clinic_union: true` — 클리닉연합. 합치기 로직에서 클리닉과 똑같이 취급되고, 강의실 배정 문서에는 "클리닉연합"으로 표기된다.
- `sessions[].note` — 부가 설명(예: "화 대체일", "모의고사", "대체실 4강의실", "웰빙관에서 수업 예정 - A관 강의실 배정 제외"). 강의실 배정 문서에 괄호로 붙어 나온다.
- `sessions[].room: "미정"` — 강의실 미정. 검증·시간표에서 자동 제외되고 HTML 시간표에는 "미정"으로만 표시.
- `sessions[].group` — 여러 반이 **같은 시간·같은 방을 의도적으로 같이 쓰는** 경우(합반, 클리닉 연합반)의 공통 태그. 같은 group은 클리닉이든 정규든 항상 하나로 합쳐진다.
  - ⚠ **group은 실제로 시간이 겹칠 때만 단다.** 안 겹치고 순서대로 이어지는 반(A반 18-20시, B반 20-22시)은 같은 방이어도 달지 않는다 — 잘못 달면 안 겹치는 두 반이 하나로 보이는 오류가 생긴다(실제로 한 번 발생). group을 달거나 고친 뒤에는 **항상 `validate.py`**로 "불필요한 group 태그"를 확인한다.
- **클리닉끼리는 자동으로 합쳐진다** — `merge_utils.merge_sessions()`가 같은 방·같은 요일에서 시간이 겹치는 클리닉 세션을 group 없이도 하나로 묶어 반명을 " / "로 나열한다(`build_room_view.py`, `build_html_xlsx.py`). **정규끼리는 절대 자동으로 합치지 않는다** — 정규가 겹치면 실제 이중배정 오류일 수 있어 `validate.py`가 잡아야 한다. 정규를 합치려면 반드시 `group`을 명시한다(예: 엄형국T A/B 합반).

**새 학기·새 프로그램마다 처음부터 만들 때**: 확정된 강의실 배정 문서(수업일정·수업시간·강의실이 반별로 정리된 텍스트/docx)를 반별로 읽으며 위 괄호 규칙으로 정규/클리닉을 나눠 채운다. 문서마다 관용구가 달라도("정규(...)=" 라벨식, "(클리닉)=" 라벨식 등) 저장은 항상 **"괄호=클리닉" 하나의 규칙**으로 통일한다.

## 4. 스크립트 (모두 `data/classes.json`을 읽어 `output/`에 쓴다)

```bash
# 1) 강의실 배정 문서 (docx) — 반명/요일-시간/강의실/수강료를 과목별로 → output/강의실_배정.docx
python3 scripts/build_room_doc.py

# 2) HTML용 시간표 엑셀 (반명 / 요일-시간 / 강의실, 정규·클리닉 각각 별도 행, 겹치는 클리닉은 한 행)
python3 scripts/build_html_xlsx.py

# 3) 요일×시간 격자 HTML — 강의실별 (요일 탭, 시간 비례 배치, 겹치는 클리닉은 한 박스)
#    출력 파일명 index.html — 깃허브 페이지 등의 기본 랜딩 페이지라서 바꾸지 말 것
python3 scripts/build_room_view.py

# 4) 요일×시간 격자 HTML — 선생님별 (행=선생님, 열=요일, 카드 스택, 강의실 링크, 주간 총 시간)
#    출력 파일명 teacher_timetable.html — 강의실 카드 링크가 index.html을 가리킴
python3 scripts/build_teacher_view.py

# 5) 학년별 시간표 HTML (학부모 공개용) — 5번 섹션 참고
python3 scripts/build_grade_view.py 고1      # 고1, 고2, 중3 ...

# 6) 검사 — 항상 마지막에 실행
python3 scripts/validate.py

# (1회성) 이번 주 토요일만 임시로 강의실이 바뀐 경우 — classes.json은 건드리지 않고
#   스크립트 안 OVERRIDES 목록(반 id, 요일, 시작시각, 새 강의실)만 이번 주 값으로 바꿔 실행
python3 scripts/build_temp_saturday.py
```

- `validate.py`가 검사하는 3가지: (1) 물리적으로 불가능한 강의실 이중배정, (2) group이 붙었지만 실제로 안 겹치는 세션(불필요한 group), (3) **합쳐진 박스 전체 미리보기** — 어떤 반들이 합쳐졌고 라벨이 "합반"인지 "클리닉 합반"인지.
- **전달 전에 (3) 목록을 항상 눈으로 확인한다.** ⚠ 정규끼리 합쳐졌는데 하나에 클리닉 세션이 섞여 전체가 "클리닉"으로 잘못 표시된 적이 있다. 각 합반이 정규만 모였으면 "합반", 클리닉이 하나라도 섞였으면 "클리닉 합반"이 맞는지 반별 요일/시간 표기(괄호 유무)와 대조한다.
- `validate.py`가 겹침을 보고하면: 실제 물리적 충돌(강의실 재배정 필요)인지, 의도된 합반(`group` 누락)인지 확인해 고친 뒤 다시 돌린다.
- `merge_utils.py`(직접 실행 X) — 2)~5)의 공용 합치기 로직:
  - `merge_sessions()` — 강의실별 시간표(3번)용. 반과 반 사이의 합반·클리닉연합.
  - `combine_class_sessions()` — 선생님별·학년별(4·5번)용. **한 반 자체의 세션을 카드 하나로** 정리:
    - 강의실 "미정" 세션은 제외(강의실 배정 전이면 아직 확정된 수업이 아니므로).
    - 같은 반이 같은 요일·시간에 강의실 2개를 동시에 쓰면(예: 수요일 클리닉연합 8·9강의실) 카드 하나 + "8·9강의실" 표기. 강의실별 시간표(`merge_sessions`)는 이 규칙을 안 쓴다(방이 기준축이라 각 방에 따로 나온다).
    - 같은 반이 같은 강의실에서 정규 끝나자마자 클리닉으로 이어지면(13시 시작, 16시 정규 끝, 16-17시 클리닉) 카드 하나 + "정규+클리닉" 라벨. 강의실이 다르면 안 합친다.

## 5. 학년별 시간표 (학부모 공개용)
- 전체가 아니라 **학년별로 따로** 만든다(`build_grade_view.py <학년>`).
- 같은 학년·과목에 병행반(예: 이의/광교 연합반 vs 유신/창현반)이 시간이 겹쳐도, 격자가 아니라 **요일 컬럼 + 카드 스택**이라 카드가 쌓일 뿐 겹치지 않는다.
- 맨 위 과목 필터 버튼(전체/국어/영어/수학/과학 등) — **처음 열면 항상 "전체"가 기본값**(버튼을 몰라도 학년 전체가 보이게). 버튼 색은 과목별 카드 색과 맞춘다.
- 반응형: 모바일은 요일 컬럼이 세로로 쌓이고, 760px 이상은 7일 가로 나열.

## 6. 산출물 갱신 공통 절차
시작점은 요청마다 다르다 — 회차·수강료부터 바뀌면 2번 절차로 확정 후 `classes.json`에 반영하고 이어서 강의실·HTML 산출물 갱신 / 강의실만 바뀌면 `sessions`만 고치고 관련 스크립트 실행(회차·수강료 문서는 다시 안 만듦) / HTML·엑셀만이면 2)·3)·4)만. 강의실 변경이나 HTML 수정 요청이 먼저 오면 그것부터 처리하고 관련 산출물은 필요하면 나중에 같이 갱신한다.
1. `classes.json`에서 해당 반의 `sessions`(또는 반 전체)를 수정/추가/삭제.
2. `validate.py`로 이중배정 확인. 있으면 `group`으로 의도된 합반을 구분하거나 실제 방 배정을 다시 묻는다.
3. 영향받는 산출물 재생성(확실치 않으면 스크립트 전부 재실행 — 빠르다).
4. 결과 파일 전달 + **무엇을 바꿨는지 간단히 요약**(사용자가 직접 대조하지 않아도 되게).

## 7. "강의실 배정 파일이 바뀌었어, 이거 보고 다시 만들어줘"
위 "강의실만 바뀌는 경우"와 다르다 — 무엇이 바뀌었는지 말해주지 않고 문서(또는 노션 페이지) 전체를 다시 보라는 상황이다.
1. **문서를 처음부터 끝까지 다시 읽는다.** 이전에 본 버전을 기억으로 재사용하지 않고 다시 fetch한다. 여러 학기가 누적된 문서(이번 학기 아래에 지난 학기·프리썸머가 남아 있는 경우)는 **"지금 이 학기" 섹션만** 보고, 오래된 섹션은 참고용.
2. **반 하나하나를 현재 `classes.json`과 대조** — 요일, 시간, 강의실, 신설/폐강 전부. 일부만 훑고 "안 바뀐 것 같다"고 넘기지 않는다.
3. **문서 안에서 모순되면 추측하지 않는다.** 같은 반이 다른 요일로 두 번 적혀 있거나 선생님 섹션이 통째로 빠진 경우(⚠ 실제 사례: 장현명T가 "수업일정"엔 있는데 "강의실 배정"엔 통째로 빠져 폐강인지 확인이 필요했음), 어느 부분이 애매한지 짚어서 묻는다.
4. 확인된 변경만 반영하고 `validate.py` — 반이 추가/삭제되면 새 충돌이 생길 수 있으니 꼭 다시 돌린다.
5. 산출물을 재생성해 전달하고, 바꾼 것과 추가 확인이 필요한 부분을 같이 요약한다.

# 구글 클라우드 이미지·TTS 생성 규칙 (2026-09-28 사용자 지시)

## 규칙 — 예외 없음
1. **한 번에 1건만 요청한다.** 이미지 여러 장을 한 요청에 묶거나, 스레드·비동기·백그라운드 프로세스 여러 개로 동시에 보내지 않는다.
2. **요청과 요청 사이에 60초를 둔다.** 직전 요청이 **끝난 시각**부터 60초. 이미지↔이미지, 이미지↔TTS, TTS↔TTS 모두 같다.
3. 모든 영상(쇼츠·롱폼)과 모든 프로젝트에 적용한다. 블로그·썸네일용 새 이미지도 마찬가지다.
4. **429 RESOURCE_EXHAUSTED(한도 초과)가 나면** 이미 만든 결과는 캐시에 남아 있으니 1분 뒤 같은 명령을 다시 실행한다. **재실행은 최대 3회**(전역 재시도 정책) — 3회 다 실패하면 멈추고 사용자에게 알린다. 인증 오류 등 다른 오류는 재시도하지 않고 바로 알린다.

5. **TTS 만드는 단위** (2026-09-29 사용자 결정): **쇼츠**는 문장·장면마다 따로 만들지 않고 전체 내레이션을 한 번에 만든 뒤 나눈다. **롱폼**은 챕터별로 나눠 만들되, 나누기 전에 영상을 몇 분으로 할지 사용자에게 먼저 묻고 정한다(`don5060-longform` [4]). 어느 쪽이든 만들기 전에 목표 길이를 사용자와 정한다.

**왜**: 2026-09-27 롱폼 이미지를 연달아 만들다 분당 한도에 걸렸다. 사용자는 한도에 걸리는 상황 자체를 피하길 원한다. 대가는 시간뿐이다(이미지 10장 ≈ 10분) — 이 시간을 줄이려고 규칙을 느슨하게 하지 않는다.

## 사용자에게 보고할 것
생성이 끝나면 요청 건수와 대략 걸린 시간을 한 줄로 알린다(예: "요청 9건, 60초 간격으로 약 10분"). 429가 났으면 몇 번째에서 났고 몇 번 재실행했는지도 적는다.

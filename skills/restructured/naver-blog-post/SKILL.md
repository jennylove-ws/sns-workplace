# 네이버 블로그 글 작성 자동화 (돈5060)

영상 한 편을 네이버 블로그 글로 바꿔 올린다: 글쓰기 → 이미지 → 에디터 입력 → 강조 서식 → 임시저장 → (확인 후) 발행.

프로젝트 루트: `C:\Users\koyon\클로드\Claude코드\코딩프로젝트\돈5060-유튜브팀` (아래 경로는 모두 이 기준)
블로그 ID: `don5060_official` / 유튜브 채널: `https://www.youtube.com/@bizdon5060`

## 기본 원칙

- **Claude in Chrome으로는 네이버에 못 들어간다**("not allowed due to safety restrictions"). 우회하지 말고 Playwright를 쓴다.
- **발행은 사용자가 그 글에 대해 "발행해줘"라고 했을 때만 누른다.** 기본은 임시저장(우상단 "저장")까지. 무인 실행 중에는 항상 임시저장까지만.
- **로그인은 사용자가 직접 한다.** 아이디·비밀번호를 대신 입력하지 않는다. 세션은 `.pw-profile/`에 남는다.
- **브라우저 창은 닫지 않는다** — 사용자가 확인하고 클립 업로드도 이어서 한다. 최소화하면 스크린샷이 멈출 수 있으니, 작업 중 창 안을 누르지 말아 달라고 알린다.
- 사용자가 수정해 둔 초안이 있으면 다시 입력하지 말고 그 초안(우상단 `저장 N` → 임시저장 목록)을 불러와 이어서 쓴다.

## 오류가 나면 — 멈추고 묻는다

- 에디터 입력 실패, 이미지 삽입 실패, 텍스트 누락, 저장·발행 오류 등 무엇이든 **그 자리에서 멈추고** 화면 문구 원문과 어디까지 됐는지 알린다.
- 같은 동작 재시도, 원인을 스스로 진단해 고치기(DOM을 뒤져 원인 찾기 포함), 다른 방법으로 우회 — 모두 사용자 지시 없이는 하지 않는다. 사용자가 "다시 해봐"라고 하면 한 번 시도한다.
- **발행은 오류가 나도 실제로 게시됐을 수 있다** — 다시 누르기 전에 블로그 글 목록부터 확인한다(중복 발행은 스팸으로 본다).
- **예외 — 이미지가 문단 중간에 들어가 문단이 갈라지는 것은 오류로 보지 않는다.** 그대로 두고 끝까지 진행한 뒤, 최종 보고에 "N번째 이미지가 '<문구>' 문단 중간에 들어가 갈라짐(그대로 둠)"이라고 한 줄 적는다.

## 0단계 — 상주 세션 띄우기

일회성 `python script.py`는 끝날 때 브라우저가 닫히므로 쓰지 않는다. **desktop-commander의 상주 REPL**로 작업한다.

```python
# start_process("python -X utf8 -i -u")   ← 한글 경로 때문에 -X utf8 필수
import glob, os, time
sp = glob.glob(r"C:\Users\koyon\*\*\*\*5060*\scripts\naver_blog_session.py")[0]
base = sp.replace(r"scripts\naver_blog_session.py", ""); os.chdir(base)
g = {"__file__": sp}
exec(open(sp, encoding="utf-8").read(), g)
for k in ("open_browser","shot","go","editor","load_draft","fill_title","fill_body",
          "insert_image","select_phrase","bold","highlight","save_draft",
          "HIGHLIGHT_YELLOW","HIGHLIGHT_PINK"):
    globals()[k] = g[k]
pg = open_browser()
```

- **여러 줄을 REPL에 붙여넣지 않는다**(조용히 씹힌다). 파일로 만들어 `exec()`하거나 한 줄씩 보낸다.
- 스크립트를 다시 `exec()`했다면 `g["_state"].update(page=pg)`로 현재 페이지를 물려준다.
- **desktop-commander가 연결되지 않으면** 일회성 스크립트로 조용히 바꾸지 말고, 사용자에게 알리고 어떻게 할지 묻는다. (일회성으로 가기로 하면: 마지막 호출에서 저장된 초안을 불러와 확인하고, 프로세스를 오래 대기시켜 브라우저를 켜 둔다.)
- Playwright가 없으면: `pip install playwright` + `python -m playwright install chromium`
- `shot()`으로 찍고 `Read`로 보면서 진행한다. 상태가 의심스러우면 추측하지 말고 한 장 찍는다.

## 1단계 — 소재 파악

`scenes/<이름>.json`(씬별 내레이션·이미지 프롬프트)과 `metadata/<이름>_description.txt`(설명란)를 읽는다. 사전 작성 대본이면 `대본/<날짜>_<슬러그>_출처.md`가 근거 자료다.

**사실 근거는 `metadata/<이름>_description.txt` 맨 끝의 `[출처]` 칸**에서 찾는다(소재 번호, 출처 파일, 법률·판례·통계 문장의 실제 링크). `[출처]`에 근거가 없는 법률·판례·통계 문장은 블로그에 옮길 때 일반론으로 바꾼다 — 대본은 각색 이야기라 근거 없는 문장이 있을 수 있지만, 블로그는 검색·AI 인용 대상이라 근거 없는 단정을 쓰지 않는다.

## 2단계 — 글 쓰기

쇼츠 대본을 그대로 옮기지 않는다. **이야기는 감정을 살려 늘리고, 뒤에 실용 정보를 붙인다.**

```
[제목]
<검색 키워드가 들어간 한 줄. 결말은 숨긴다>

[본문]
<도입: "우리 집 얘기 같은데" 하고 들어오게. 첫 100자 안에 무엇을 다루는지 드러내고, 채널명 "돈 5060"을 한 번>

■ <전환점 소제목>
■ <일반화 — 왜 이런 일이 생기나>
■ <실천 — "이 N가지는 꼭 확인하세요">
1. <항목 제목>
<설명 2~3문장>
■ 마지막으로
<교훈 — 노후 자산을 지킨다로 수렴> <댓글 유도 질문>

<마무리 블록>
```

완성한 글은 `metadata/<이름>_naver_blog.md`에 위 `[제목]`/`[본문]` 형식으로 저장한다(`load_draft()`가 파싱).

지킬 것:
- **소제목은 `■ `로 시작**(형광펜을 칠할 자리).
- **실천 체크리스트를 꼭 넣는다** — 검색 유입 독자가 저장·공유할 이유다. 금액·기간·절차 같은 그 글만의 구체 정보를 넣는다.
- **법·제도는 일반론까지만.** 판례 번호·사건명·통계를 지어내지 않고, "사안마다 다르니 전문가와 상담"의 여지를 남긴다.
- **1인칭으로 쓰지 않는다.** 사연은 3인칭("영상 속 주인공은…", "한 어머니는…"), 독자에겐 2인칭("여러분은 어떠셨나요?"). `나는/저는/내 남편/우리 집`이 사건을 겪은 것처럼 쓰지 않는다 — 가상의 이야기가 운영자 실화로 읽힌다.
- 존댓말, 시니어 존중. 명령조("~하지 마라")는 쓰지 않는다.
- 결말·피해 액수를 제목에 다 쓰지 않는다.

### SEO·GEO

- **네이버가 막는 것**: AI로 비슷한 글 대량 생성, 비슷한 내용 반복 발행, 키워드 반복, 낚시성 제목, 숨긴 텍스트, 링크 도배. 이 채널은 같은 소재 풀에서 계속 쓰므로 특히 조심한다 — 소제목·구성을 글마다 바꾸고, 그 글에만 있는 정보를 넣는다.
- "1,500자 / 사진 5장 / 키워드 3~5회"는 공식 기준이 아니다. 숫자를 맞추려고 늘리지 않는다.
- **제목**: 실제로 검색창에 칠 표현을 자연스럽게. **첫 문단** 100자 안에 주제.
- **C-Rank**: 한 카테고리("손해없는 처세·관계")에 꾸준히 쌓는다.
- **GEO**: 소제목마다 첫 문장을 한 문장 답변으로(결론 먼저). 형용사 대신 숫자·기간·고유명사. 질문형 소제목도 좋다. 지어낸 출처·통계는 쓰지 않는다.

## 3단계 — 이미지 만들기

블로그 본문 폭 966px. 세로 썸네일은 쓰지 않는다.

- 그 영상의 씬 이미지는 `cache/images/`에 있다. 파일명은 해시라 수정 시각 순서로는 못 찾는다 — `produce_video.py`의 `_cache_path`로 씬 프롬프트의 캐시 키를 계산해 찾는다(스타일 없는 예전 키도 확인). 흑백 등 스타일 씬은 키에 스타일 이름이 들어간다.
- `scripts/make_blog_images.py`:
  - **표지 1장**(`make_cover`, 16:9, 하단 그라데이션 + 흰 제목 글씨) — 본문 맨 위.
  - **본문 3장**(`make_body`, 3:2, 글자 없음) — 전환점·반전·마무리 자리.
- **대표 이미지는 반드시 표지가 아닌 본문 이미지로 지정한다**(필수 단계). 표지 글자는 목록 썸네일에서 잘려 지저분하다. 이미지를 클릭하면 왼쪽 위에 어두운 "✓ 대표" 배지가 뜨고, 그걸 누르면 초록색이 된다 — 스크린샷으로 표지에서 배지가 빠졌는지 확인. 안 되면 멈추고 알린다. 최종 보고에 "대표 이미지: 본문 N번째"라고 적는다.
- 만든 뒤 이미지를 직접 열어 확인하고, 임시 컨택트시트는 지운다.

## 4단계 — 입력 순서

로그인 후 글쓰기: `https://blog.naver.com/GoBlogWrite.naver` (에디터는 `mainFrame` iframe 안).

1. `load_draft()` → `fill_title(t)` → `fill_body(b)` — **본문은 사인오프 + 영상 링크까지만** 넣는다.
2. 직후 `.se-text-paragraph`를 전부 뽑아 원고와 **줄 단위로 대조**한다. 빠진 줄이 있으면 스스로 채우지 말고 알린다.
3. 이미지 삽입(5단계) → 강조 서식(6단계).
4. **맨 마지막에** 본문 끝(영상 링크 줄)을 눌러 End → Enter 후, 이웃 CTA → 채널 CTA → 채널 링크 → 해시태그를 한 줄씩 입력(줄마다 Enter 후 1~1.5초 대기). 입력 뒤 끝부분을 출력해 CTA 두 번째 문장이 온전한지 확인.
5. 해시태그 서식: `select_phrase(<해시태그 줄>)` → `button[class*='font-size']` → `button[class*='font-size-code-fs11-button']` → 다시 선택 → `button.se-font-color-toolbar-button`으로 팔레트 열기 → **맨 왼쪽 세로줄 아래에서 세 번째 칸**(rgb 226,226,226)을 스크린샷 보고 **좌표로 클릭**(CSS 선택자로는 클릭이 안 된다). 확인: span에 `se-fs11`, `color: rgb(226, 226, 226)`.

한글은 `insert_text`로 넣는다(한 글자씩 `type`하면 IME 문제). `fill_body`는 줄마다 `insert_text` + `Enter`.

## 5단계 — 이미지 삽입

```python
insert_image("<첫 문단 앞부분>", cover, at_start=True)   # 맨 위
insert_image("■ <소제목>", img1)                          # 짧은 한 줄 문단 뒤가 안전
```
- 두 줄 이상 문단은 `click()`이 가운데를 눌러 문단이 갈라지기 쉽다. 짧은 한 줄 문단(소제목) 뒤에 넣는다. 맨 앞은 첫 줄 좌상단을 마우스로 클릭한 뒤 `Home`.
- 삽입 뒤 표지가 맨 위에 있는지 스크린샷으로 확인한다. 아니면 보고에 적는다(갈라짐 예외 규칙대로 계속 진행).
- 삽입 후 문단 목록을 다시 대조해 텍스트가 빠지지 않았는지 본다.

## 5.5단계 — 링크 카드

영상·채널 링크는 **URL만 한 줄에 넣으면** 네이버가 자동으로 카드로 바꾼다(`insert_link_card()`는 쓰지 않는다 — 카드로 안 바뀐다). 채널 링크가 파란 글자로 남아도 정상이니 다시 시도하지 않는다. 저장 뒤 스크린샷으로 확인만 한다.

## 6단계 — 강조 서식

JS로 만든 선택은 에디터가 인식하지 못한다 — `select_phrase()`가 실제 마우스 드래그로 선택한다. 성공 여부는 `getSelection()`이 아니라 DOM의 `<b>`/`<mark>` 개수로 확인한다.

- **형광펜**: `■` 소제목 전부 노랑(`HIGHLIGHT_YELLOW`), **결론 소제목("■ 마지막으로") 하나만 핑크**(`HIGHLIGHT_PINK`). 본문 문장에는 거의 쓰지 않는다.
- **볼드** 8~10곳: 핵심 수치·사실, 반전 문장 한 줄, **체크리스트 번호 항목 제목 전부**, 결론 문장.
- 구절은 한 문단(한 텍스트 노드) 안에 있어야 찾힌다.

## 7단계 — 임시저장 → 발행

임시저장 전 체크: ① 대표 이미지를 본문 이미지로 지정 ② 본문 대조 완료 ③ 표지 위치 확인.
`save_draft()`로 임시저장한 뒤 사용자에게 알린다:
- 제목과 구성, 이미지 위치, 대표 이미지, 볼드·형광펜 위치(핑크가 어디인지)
- 문단 갈라짐이 있었으면 한 줄
- **발행은 누르지 않았다**는 것

사용자가 "발행해줘"라고 하면: `button[class*="publish_btn"]`로 패널을 열어 카테고리(**손해없는 처세·관계**)·전체공개·발행 시간(현재)을 스크린샷으로 확인한 뒤 `button[class*="confirm_btn"]`. (`button:has-text('발행')`은 숨은 "예약 발행" 버튼이 먼저 잡히니 쓰지 않는다.) 발행 후 URL(`logNo`)과 **글 제목**을 기록해 클립에 넘긴다.

작업 중 만든 임시 파일(`_naver_shot.png` 등)은 지운다.

## 전략 갱신

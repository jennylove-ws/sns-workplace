# 작업을 스킬로 저장하기

## 원칙 (2026-09-29 사용자 결정)
- **모든 스킬의 원본은 claude.ai 계정 한 곳이다.** 채팅·데스크톱 앱·Claude Code 웹 모두 계정 스킬을 읽는다. 로컬 `~/.claude/skills/`나 프로젝트 `.claude/skills/`, GitHub 저장소에 따로 설치하지 않는다(같은 스킬이 두 벌 생겨 내용이 어긋난다).
- **스킬 수정은 채팅창에서 한다.** 채팅창만 스킬 저장 버튼이 뜬다. Claude Code(웹·데스크톱)에서 나온 수정 사항은 **Notion "🛠 스킬 수정 대기" 목록에 적어두고**, 사용자가 채팅창에서 "스킬 수정 대기 목록 반영해줘"라고 하면 한 번에 반영한다 — zip 다운로드·업로드를 없애기 위해서다.
- **작업이 끝난 뒤에 저장한다.** 실제로 해 보고 확인된 절차·함정·결정만 담는다.
- **기존 내용은 하나도 빠뜨리지 않는다.** 고칠 때는 현재 내용을 전부 읽고, 바뀐 규칙만 교체한다.

## Notion "🛠 스킬 수정 대기" 목록
- DB: `https://app.notion.com/p/d36d3ad41c904886978891afedc792c9` (data source `collection://10c0b634-3fac-4fd2-b539-dc0bd709420c`, 위치: 🏠 내 노션 메인 아래)
- 속성: `수정 요약`(제목) / `스킬`(스킬 이름 그대로) / `상태`(대기·반영완료·보류) / `종류`(규칙 추가·규칙 변경·규칙 삭제·새 스킬·과거 실수 기록) / `위치`(SKILL.md 어느 섹션·문장) / `바꿀 내용` / `이유` / `등록한 곳`(Claude Code 웹·Claude Code 데스크톱·채팅) / `등록일` / `반영일`

## A. Claude Code(웹·데스크톱)에서 — 대기 목록에 등록
1. 반영할 내용을 정리한다(새 스킬인지, 어느 스킬 수정인지 — 아래 "작성 규칙" 1번).
2. **항목 하나 = 스킬 하나의 변경 하나.** 채팅창은 이 작업 내용을 모르니 **그 항목만 읽어도 고칠 수 있게** 쓴다:
   - `위치`: "0. 시작 전 반드시 확인 3번", "⚠ 과거 실수" 처럼 섹션을 정확히
   - `바꿀 내용`: 넣을 문장 **그대로**. 바꾸는 거면 `이전: ... → 새: ...`. 경로·ID·숫자는 정확히
   - `이유`: 한 줄. 실수·지적 때문이면 무슨 일이 있었는지
   - `상태` = 대기, `등록한 곳`, `등록일` = 오늘
3. 등록 전에 같은 스킬의 `대기` 항목을 확인해 중복이면 합친다.
4. 사용자에게 한 줄로 알린다: "스킬 수정 대기 목록에 N건 등록했어요(스킬: ...). 채팅창에서 '스킬 수정 대기 목록 반영해줘'라고 하시면 돼요."
5. **zip은 예외적으로만 만든다**: 사용자가 zip을 달라고 할 때 / Notion 연동이 없을 때 / 스크립트·엑셀·JSON 등 **파일 자체**를 바꿔야 해서 글로 전달할 수 없을 때(zip 방법은 C).

## B. claude.ai 채팅에서 — 직접 수정 / 대기 목록 반영
- **대화 중 바로 반영 요청이면**: 해당 스킬을 고쳐 저장 버튼이 뜨는 스킬 파일로 준다.
- **"스킬 수정 대기 목록 반영해줘"면**:
  1. 위 DB에서 `상태 = 대기` 항목을 전부 읽는다(Notion 연동이 없으면 연동이 필요하다고 알린다).
  2. **스킬별로 묶어서**, 각 스킬의 현재 내용을 먼저 전부 읽은 뒤 항목들을 반영한다. 항목끼리 충돌하거나 `위치`를 못 찾거나 뜻이 애매하면 그 항목은 반영하지 말고 `보류`로 두고 이유를 알린다.
  3. 스킬마다 저장 버튼이 뜨는 스킬 파일로 준다(여러 개면 스킬별로). 버튼이 안 뜨면 파일을 내려받아 설정 → 기능 → 스킬에서 올리라고 안내한다.
  4. 반영한 항목은 `상태 = 반영완료`, `반영일 = 오늘`로 바꾼다.
  5. 보여주기: 스킬별로 무엇이 바뀌었는지 1~3줄, 보류된 항목과 이유, "저장 버튼을 눌러야 실제로 반영된다"는 한 줄.

## C. zip으로 전달할 때 (A-5의 예외 상황)
`<스킬이름>.zip` — zip 안의 최상위는 스킬 폴더 하나(`<스킬이름>/SKILL.md`). 데스크톱이면 `C:\Users\koyon\OneDrive\바탕 화면\웹 업로드용 스킬\`에 저장하고 파일로 보내 준다. 올리는 곳: claude.ai → 설정 → 기능(Capabilities) → 스킬 → 업로드. 기존 스킬 수정이면 예전 것을 지우고(또는 교체) 새 zip을 올리라고 알려 준다.

## 작성 규칙 (어느 환경이든)
1. **새 스킬인지, 기존 스킬 수정인지 판단한다.** 비슷한 스킬이 있으면(스킬 목록의 `anthropic-skills:` 접두사 포함) 새로 만들지 말고 그 스킬을 고친다. 고칠 때는 현재 내용을 먼저 읽는다.
   - **규칙이 바뀌면 옛 규칙은 지우고 새 규칙만 남긴다** — "9/22엔 A → 9/23에 B로 원복" 같은 이력을 본문에 쌓지 않는다.
   - 같은 실수를 막아 주는 이유는 한 줄로 남긴다(예: "👇 이모지를 넣으면 문장이 사라짐 → 넣지 않는다"). 벌점·지적을 받았던 실수는 "⚠ 과거 실수" 칸에 한 줄씩.
   - 이번 수정과 관계없는 다른 규칙은 건드리지 않는다.
2. **SKILL.md 표준 구조** (중요한 건 맨 앞과 맨 끝에):
   ```
   ---
   name: 영문 소문자·하이픈 (기존 스킬을 고치면 이름을 바꾸지 않는다)
   description: 언제 쓰는지 + 사용자가 실제로 할 법한 말 + 비슷한 다른 스킬과의 경계
   ---
   # 제목 + 한두 줄 요약
   ## 0. 시작 전 반드시 확인 (놓치기 쉬운 규칙 먼저, 짧게)
   ## 1. 작업 순서
   ## 2~. 세부 규칙 (주제별 섹션)
   ## 전달 전 최종 점검 (체크리스트)
   ## 다른 스킬과의 경계
   ## ⚠ 과거 실수 (한 줄씩, 이유 포함)
   ## 결정 배경 (필요할 때만, 맨 끝 — 다시 뒤집지 않도록)
   ## 참고 파일
   ```
   - 지금 유효한 규칙만 적는다. 경로·ID 같은 구체적 값은 그대로.
   - **같은 값(명단, 전화번호, 링크 등)은 한 곳에만** 적고 다른 곳은 그 파일을 가리킨다.
   - 다른 스킬을 참조하면 **그 스킬이 지금 계정에 켜져 있는지** 확인한다(꺼져 있거나 없는 스킬을 필수처럼 가리키지 않는다).
   - 스크립트·참고 문서는 같은 폴더(`scripts/`, `references/`). 본문이 길어지면 세부는 `references/`로 빼고 본문엔 "언제 그 파일을 볼지"만.

## 하지 말 것
- 사용자가 저장 버튼을 누르거나 zip을 올리기 전에 "저장 완료"라고 말하지 않는다 — "대기 목록에 등록했다" / "저장할 파일을 만들었다"고 말한다.
- 비밀번호·API 키·토큰 같은 값을 스킬이나 대기 목록에 넣지 않는다(`.env` 같은 위치만 적는다).
- 한 번 쓰고 말 내용(오늘 날짜의 할 일 목록 등)은 스킬에 넣지 않는다. 반복될 절차와 규칙만.

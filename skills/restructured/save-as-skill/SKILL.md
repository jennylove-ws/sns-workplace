# 스킬 저장·수정 (노션이 원본)

## 원칙 (2026-09-29 사용자 결정)
- **모든 스킬의 원본은 Notion "🧩 스킬 원본 (메인 저장소)"다.** claude.ai 계정의 스킬은 노션의 **복사본**이다.
- **수정은 작업한 Claude가 노션에서 직접 한다.** 어느 창(채팅·Claude Code 웹·데스크톱)이든 같다. 작업 맥락을 아는 Claude가 고쳐야 정확하기 때문이다.
- **claude.ai 채팅창은 복사만 한다.** '반영 필요'인 스킬을 노션에서 **그대로** 가져와 저장 버튼을 만든다. 내용을 해석하거나 고치지 않는다.
- **계정 스킬을 채팅창에서 직접 고치지 않는다.** 그러면 노션 원본과 어긋난다. 채팅창에서 스킬 수정 요청이 오면 먼저 노션을 고치고(A), 그다음 복사(B)한다.
- 로컬 `~/.claude/skills/`, 프로젝트 `.claude/skills/`, GitHub 저장소에 스킬을 설치하지 않는다(세 번째 사본이 생긴다).
- **작업이 끝난 뒤에 저장한다.** 실제로 해 보고 확인된 절차·함정·결정만 담는다. **기존 내용은 하나도 빠뜨리지 않는다.**

## A. 스킬 고치기 — 작업한 Claude가 (어느 창이든)
1. **노션에서 현재 스킬을 통째로 받는다**: `notion-download-skill`(페이지 ID) → tar.gz → 압축 해제. 기억이나 계정 사본을 기준으로 고치지 않는다(노션이 최신이다). **고칠 대상은 `_source/SKILL.md`**(루트의 SKILL.md는 노션이 서식을 바꾼 보기용이라 쓰지 않는다)와 나머지 파일들이다.
2. 아래 "작성 규칙"대로 고친다(바뀐 규칙만 교체, 나머지는 그대로).
3. **노션에 다시 올린다**: 고친 `_source/SKILL.md`를 루트 `SKILL.md`로도 복사한 뒤(둘은 항상 같은 내용), 스킬 폴더(`<스킬이름>/SKILL.md`, `<스킬이름>/_source/SKILL.md`, 나머지 파일)를 tar.gz로 묶어 `notion-upload-skill`(action=prepare → 받은 upload_url에 헤더 그대로 PUT → action=complete). 새 스킬이면 먼저 DB에 페이지를 만들고 올린다.
4. 속성 갱신: `계정 반영` = **반영 필요**, `노션 수정일` = 지금(날짜+시각), `수정 내용` = 무엇을 왜 바꿨는지 한두 줄.
5. 사용자에게 한 줄: "노션 스킬 원본을 고쳤어요(스킬: ...). 채팅창에서 '노션 스킬 반영 필요한 거 업데이트 버튼 만들어줘'라고 하시면 계정에 반영돼요."
- Notion 연동이 없는 창이면: 고친 스킬을 zip으로 만들어 주고(C), 노션에도 올려야 한다고 알린다.

## B. 계정에 반영하기 — claude.ai 채팅창에서 ("노션 스킬 반영 필요한 거 업데이트 버튼 만들어줘")
1. DB에서 **`계정 반영 = 반영 필요`**인 페이지를 전부 찾는다.
2. 스킬마다 `notion-download-skill`로 받은 tar.gz를 풀고, **`_source/SKILL.md`를 루트 `SKILL.md` 자리에 덮어쓴 뒤 `_source/` 폴더는 뺀다.** 그 스킬 폴더를 `.skill` 파일(= 스킬 폴더를 통째로 담은 zip)로 묶어 저장 버튼을 띄운다. **내용을 한 글자도 고치지 않는다.** `_source/SKILL.md`가 없으면(사람이 노션에서 새로 만든 스킬 등) 멈추고 알린다 — 서식이 바뀐 본문을 그대로 쓰지 않는다.
   - 다운로드가 막히면(네트워크 제한 등) 페이지를 `fetch`해서 재구성하지 말고 — 서식이 바뀔 수 있다 — 멈추고 사용자에게 알린다(Claude Code에서 zip을 만들어 달라고 하면 된다).
3. 버튼을 만든 스킬은 `계정 반영` = **반영됨**, `계정 반영일` = 지금.
4. 보여주기: 반영한 스킬 목록과 각 `수정 내용`, 그리고 "**저장 버튼을 눌러야 실제로 반영돼요**" 한 줄. 사용자가 누르지 못한 게 있다고 하면 그 스킬을 다시 `반영 필요`로 돌린다.

## C. zip으로 전달할 때 (Notion이 안 될 때만)
`<스킬이름>.zip` — zip 안의 최상위는 스킬 폴더 하나(`<스킬이름>/SKILL.md`). 데스크톱이면 `C:\Users\koyon\OneDrive\바탕 화면\웹 업로드용 스킬\`에 저장. 올리는 곳: claude.ai → 설정 → 기능 → 스킬 → 업로드(기존 스킬이면 교체). 이 경우에도 나중에 노션 원본에 같은 내용을 올린다.

## 작성 규칙
1. **새 스킬인지, 기존 스킬 수정인지 판단한다.** 비슷한 스킬이 있으면 새로 만들지 말고 그 스킬을 고친다.
   - **규칙이 바뀌면 옛 규칙은 지우고 새 규칙만 남긴다** — "9/22엔 A → 9/23에 B로 원복" 같은 이력을 본문에 쌓지 않는다.
   - 같은 실수를 막는 이유는 한 줄로(예: "👇 이모지를 넣으면 문장이 사라짐 → 넣지 않는다"). 벌점·지적을 받았던 실수는 "⚠ 과거 실수" 칸에 한 줄씩.
   - 이번 수정과 관계없는 규칙은 건드리지 않는다.
2. **SKILL.md 표준 구조** (중요한 건 맨 앞과 맨 끝에):
   ```
   ---
   name: 영문 소문자·하이픈 (기존 스킬을 고치면 이름을 바꾸지 않는다)
   description: 언제 쓰는지 + 사용자가 실제로 할 법한 말 + 비슷한 다른 스킬과의 경계
   ---
   # 제목 + 한두 줄 요약
   ## 0. 시작 전 반드시 확인 (놓치기 쉬운 규칙 먼저, 짧게)
   ## 1. 작업 순서
   ## 2~. 세부 규칙 (주제별 섹션)
   ## 전달 전 최종 점검 (체크리스트)
   ## 다른 스킬과의 경계
   ## ⚠ 과거 실수 (한 줄씩, 이유 포함)
   ## 결정 배경 (필요할 때만, 맨 끝 — 다시 뒤집지 않도록)
   ## 참고 파일
   ```
   - 지금 유효한 규칙만. 경로·ID 같은 구체적 값은 그대로.
   - **같은 값(명단, 전화번호, 링크 등)은 한 곳에만** 적고 다른 곳은 그 파일을 가리킨다.
   - 다른 스킬을 참조하면 **그 스킬이 지금 켜져 있는지** 확인한다(꺼져 있거나 없는 스킬을 필수처럼 가리키지 않는다).
   - 본문이 길어지면 세부는 `references/`로 빼고 본문엔 "언제 그 파일을 볼지"만.

## 하지 말 것
- 저장 버튼을 누르기 전에 "저장 완료"라고 말하지 않는다 — "노션 원본을 고쳤다" / "저장 버튼을 만들었다"고 말한다.
- 비밀번호·API 키·토큰 같은 값을 스킬에 넣지 않는다(`.env` 같은 위치만 적는다).
- 한 번 쓰고 말 내용(오늘 할 일 목록 등)은 스킬에 넣지 않는다. 반복될 절차와 규칙만.

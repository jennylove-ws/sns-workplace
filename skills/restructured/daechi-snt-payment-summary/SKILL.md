# 학부모 결제 금액 정리 (카톡 결제 내역 / 학기 수강료 정리표)

학부모 한 가정에 보낼 "이번에 얼마를 내야 하는지" 정리를 만든다. 결과물은 **파일이 아니라 채팅창 텍스트**다(사용자가 .docx 등 파일을 명시하면 그때만 파일).

> 이 스킬은 예전의 `daechi-snt-payment-summary`(카톡 결제 내역)와 `daechi-snt-tuition-invoice`(수강료 정리표)를 합친 것이다. 두 모드는 **할인 기본값이 서로 다르니** 반드시 0단계에서 모드부터 정한다.

## 0. 시작 전 반드시 확인 (놓치기 쉬운 것 먼저)

1. **모드를 정한다.**

   | | (A) 카톡 결제 내역 | (B) 학기 수강료 정리표 |
   |---|---|---|
   | 이런 말이 나오면 | "결제 내역 정리해줘", "카톡으로", "이번 달 낼 금액", 이월금·리뷰 차감 얘기 | "수강료 정리해줘", "이번 달 결제금액", "학부모한테 보낼 수강료 안내", "N일부터 계산해줘" |
   | 금액 출처 | 사용자가 대화·캡처·문서로 준 과목별 금액 그대로 | tuition-schedule 스킬의 `data/classes.json` (+필요시 `gen_dates.py`) |
   | **할인** | **기본 없음.** 사용자가 명시적으로 요청할 때만 적용하고, 묻지 않는다 | **만들기 전에 먼저 물어본다** (할인 여부·몇 %·어떤 과목) |
   | 기결제 금액 | (언급되면 반영) | **만들기 전에 먼저 물어본다** |
   | 첫 줄 / 마지막 줄 | `어머님~ 결제 내역 정리해서 드립니다^^` … 결제링크 발송 여부 질문 | `[학기명]` … `■ 최종 결제 금액` / `= 000,000원` |

   어느 쪽인지 애매하면 "카톡으로 보낼 결제 내역인가요, 과목별 회차·수강료 정리표인가요?"라고 한 번 묻는다.
2. **숫자는 지어내거나 암산하지 않는다.** 금액·회차는 사용자가 준 값이나 문서/`classes.json` 값을 그대로 쓰고, 날짜를 다시 계산해야 하면 반드시 tuition-schedule 스킬의 `scripts/gen_dates.py`를 쓴다.
3. **할인율·기결제 금액은 어디에도 저장돼 있지 않다.** 이전 대화에서 쓰던 값을 재사용하거나 추측하지 않는다. 일부 과목 할인인지 전체 할인인지 확인 없이 넘겨짚지 않는다(예: "국영수만 10%").
4. **(A) 이월금·네이버 리뷰 차감**처럼 빼야 할 항목이 대화나 캡처에 이미 나왔으면 사용자가 다시 말하지 않아도 반드시 챙긴다.
5. **금액은 천 단위 콤마**(`1,325,000원`). 최종 문구를 주기 전에 모든 계산을 파이썬 등으로 재검산한다 — 학부모에게 바로 나가는 금액이다.

## 모드 A — 카톡 결제 내역

### A-1. 금액과 할인
- 과목별 금액은 사용자가 대화로 알려주거나 캡처/문서로 보여준 값을 그대로 쓴다.
- **기본값은 할인 없음.** "할인해줘", "3과목 10% 할인해줘", "OO 할인 적용해줘"처럼 명시적으로 요청했을 때만 할인한다. 요청이 없으면 원래 금액을 더한 합계가 최종 금액이다.
- 할인은 사용자가 말한 %·과목 그대로 반영한다. 일부 과목만 지정했으면 그 과목만 할인하고 나머지는 원가로 더한다. 애매하면 확인한다.
- 다른 옵션(오픈특가, 단독 가격 등)과 비교해 달라고 하면, **어느 금액끼리 비교하는지**(예: 해당 과목 할인 전 금액 vs 대체 옵션 금액, 또는 전체 할인 총액 vs 대체 옵션으로 바꿨을 때 총액)가 명확하지 않을 때 지어내지 말고 확인한다.

### A-2. 이월/차감 항목
- 전월 이월금, 네이버 리뷰 차감 등 빼야 할 항목이 대화·캡처에 있으면 찾아서 반드시 포함한다(이전에 확인된 값이 있으면 사용자가 다시 말하지 않아도 챙긴다).
- 여러 과목에 걸쳐 있으면(국어 이월금, 과학 이월금 등) **과목/사유별로 따로** 적는다 — 하나의 숫자로 뭉뚱그려 빼지 않는다.
- 차감 항목이 없으면 이 부분은 생략한다.

### A-3. 회차 내역 (노션 문서가 있을 때만)
- 노션에 수강회차·금액 문서 링크가 있으면 그 문서의 실제 수업 날짜/총 회차(예: `10/7, 14, 21, 28 (총 4강)`)를 금액 줄 바로 아래에 적는다. 날짜는 문서 값을 그대로 쓰고 새로 계산하지 않는다(재계산이 필요하면 `gen_dates.py`).
- 노션 링크가 없거나 사용자가 "이번엔 회차는 안 넣어도 된다"고 하면 금액만으로 정리한다 — 회차를 억지로 채우지 않는다.

### A-4. 형식 — 예시는 기본틀일 뿐, 답안이 아니다
매번 과목 수·할인 여부·차감 항목·비교 필요성을 보고 **학부모가 가장 쉽게 이해하는 간결한 구성**을 판단한다.

```
어머님~ 결제 내역 정리해서 드립니다^^

국어 (전진선T): 290,000원 → 10% 할인 금액 261,000원
공수2 (유재필T): 437,500원 → 10% 할인 금액 393,800원
과학 (노현석T): 220,000원 → 10% 할인 금액 198,000원

여기에 9월달에 미적용됐던 3과목 10% 할인분(126,000원)을 이번에 차감하면

■ 최종 결제 금액
= 852,800원 − 126,000원 = 726,800원

* 과학 한 과목만 오픈기념 15만원으로 계산하는 것보다, 3과목 10% 할인 적용한 금액이 24,700원 더 저렴합니다.

아버님 번호로 결제링크는 준비되어 있는데, 10% 할인 최종 결제 금액인 726,800원으로 결제링크 보내드릴까요?
```

규칙 (위 "기본틀일 뿐" 원칙이 우선):
- 첫 줄은 `어머님~ 결제 내역 정리해서 드립니다^^` (받는 사람이 아버님이면 `아버님~ 결제 내역...`), 그 다음 빈 줄.
- 과목별 줄: `과목명 (선생님T): 원래금액원`. 할인이 있으면 같은 줄에 `→ N% 할인 금액 할인금액원`, 없으면 화살표 없이 원래 금액만. 회차를 넣을 때는 금액 줄 바로 아래 `날짜, 날짜... (총 N강)`. 과목 사이는 줄바꿈만, 빈 줄 없음.
- **같은 숫자를 두 번 보여주지 않는다.** 예: `합계: 000원` / `10% 할인 합계: 000원`을 따로 보여주고 바로 이어서 `■ 최종 결제 금액 = 000원 − 000원 = 000원`처럼 같은 숫자를 반복 노출하지 않는다. `합계:` / `N% 할인 합계:` 줄은 선택사항 — 최종 결제 금액 계산식에 이미 그 숫자가 들어가면 생략한다. 과목이 많거나 계산이 복잡해서 중간 합계가 있어야 이해하기 쉬울 때만 넣는다.
- 항목이 1~2개면 과목별 줄 + 곧바로 최종 금액으로 끝내도 된다(중간 합계 불필요).
- 차감 항목이 있으면 과목 목록 다음 빈 줄, `여기에 <설명>(<금액>원)을 이번에 차감하면`처럼 자연스러운 문장으로. 여러 개면 항목별로 이유를 구분.
- 빈 줄 → `■ 최종 결제 금액` → 다음 줄 `= 계산식 = 최종금액원`(원래/할인 후 금액과 차감액이 다 보이게). 이 한 줄이 위의 합계 줄들을 대신한다. 차감·비교가 없으면 계산식 없이 금액만 보여줘도 된다(억지로 계산 과정을 늘어놓지 않는다).
- 비교/참고는 요청했거나 참고가 될 때만, 최종 금액 다음 빈 줄에 `* 참고로, ...` 한 문장으로 **핵심 차액과 결론만**. 중간 계산을 늘어놓지 않는다.
- 마지막은 빈 줄 다음 **결제링크 발송 여부 질문**(예: `아버님 번호로 결제링크는 준비되어 있는데, N% 할인 최종 결제 금액인 000,000원으로 결제링크 보내드릴까요?`). 호칭은 실제로 결제링크를 받을 사람(아버님/어머님)에 맞춘다.

## 모드 B — 학기 수강료 정리표

학년·과목을 받으면 과목별 회차와 수강료를 정리하고 할인·기결제를 반영한 최종 결제 금액까지 계산한다.

### B-1. 데이터 가져오기
1. 요청한 학년(중3, 고2 등)·과목(특정 과목일 수도, 전체일 수도)에 해당하는 반을 tuition-schedule 스킬의 `data/classes.json` → `classes`에서 찾는다. 같은 학년·같은 과목에 병행반이 여러 개 걸리면 사용자에게 확인한다.
2. 날짜 지정 없이 "정리해줘"만 하면 각 반의 `pricing.count`/`pricing.total`(이미 계산된 회차)을 그대로 쓴다. 재계산하지 않는다.
3. 요일 패턴·단가·정액 여부 등이 `classes.json`에 없거나 애매하면 지어내지 말고 확인한다.
4. **만들기 전에** 할인(있는지, 몇 %, 어떤 과목)과 이미 결제한 금액을 물어본다(요청에 이미 있으면 다시 묻지 않는다).

### B-2. 특정 날짜부터 재계산 ("29일부터 계산해줘", "8/5부터만")
그 반의 원래 기간 중 지정일 이후 남은 회차만 다시 뽑는다. **날짜는 손으로 세지 말고** `gen_dates.py`를 그 반의 요일 패턴으로 다시 호출한다: `--start <지정일> --end <원래 종료일>`(종료일은 원래 회차 목록의 마지막 날짜, 사용자가 끝나는 날도 지정했으면 그 날짜).

```
원래: [중3]_국어 (엄태욱T) - 수 18:00~21:00 [회당 75,000원]
      7/22, 29, 8/5, 12 (총 4강, 300,000원)
"29일부터 계산해줘" -> 8/5, 12 (총 2강, 150,000원)
```
(예시 숫자일 뿐 — 실제로는 항상 `gen_dates.py` 결과를 쓴다.)

금액 계산은 과금 방식별로:
1. **회당 수강료제(per_session)**: 남은 회차 수 × 회당 단가.
2. **1개월 정액제(flat_monthly)**: 정액은 "주당 수업 횟수 × 4주" 기준이다 — **주 1회 = 4강, 주 2회 = 8강, 주 3회 = 12강.** 무조건 4로 나누지 말고, 반의 `sessions`/요일 패턴에서 주당 횟수를 먼저 확인해 기대 회차 = 주당 횟수 × 4로 잡는다(화·목 = 주 2회, 월·수·금 = 주 3회).
   - 원래 기간 전체 회차가 **기대 회차와 정확히 같으면**: 회당 단가 = 정액 ÷ 기대 회차로 역산 → 남은 회차 × 단가. 각주 `※ 1개월 정액(주 N회수업 × 4주 = M강 기준)을 회당 OO원으로 환산해서 계산함`(주당 횟수까지 밝힌다).
   - **기대 회차와 다르면**(공휴일 등으로 7강 또는 9강): 4주 기준 가정이 안 맞으니 **절대 임의로 나누지 말고 먼저 묻는다.** 예: "이 반은 주 2회 수업이라 기대 회차가 8강인데, 이번 달엔 실제로 7회 수업이라 4주 기준 정액을 그대로 나누기 어려워요. 정액 ÷ 7회(실제 회차)로 계산할까요, 아니면 원래 기준(정액 ÷ 8강)으로 계산할까요?" 답을 받으면 그 기준으로 계산하고 결과에 각주로 남긴다.

여러 반 중 일부만 날짜 지정이 있으면 **지정된 반만** 재계산하고 나머지는 원래 값을 쓴다.

### B-3. 형식 (이 형식을 그대로 따른다)
```
[썸머]
[중3]_공수 1·2 (정수인T) - 월·금 18:30-22:00 [회당 62,500원]
7/20, 24, 27, 31, 8/3, 7, 10, 14 (총 8강, 500,000원)
[중3]_국어 (엄태욱T) - 수 18:00~21:00 [회당 75,000원]
7/22, 29, 8/5, 12 (총 4강, 300,000원)
[중3]_영어 (MAXIM) - 화·목 19:00~22:00 [회당 50,000원]
7/21, 23, 28, 30, 8/4, 6, 11, 13 (총 8강, 400,000원)
총합계: ~~1,325,000원~~
할인 혜택: 국영수 10% 할인 
-> 총 1,192,500원
- 772,500(이미 결제하신 금액)
■ 최종 결제 금액
= 420,000원
```
- 학기/기간 이름은 맨 위 대괄호로 한 번(`[썸머]`, `[9월]`).
- 반 정보 줄: `[학년]_과목 (선생님T) - 요일 시작-종료 [회당 00,000원]`. 정액제는 `[1개월 000,000원]`로 쓰고 회차 수와 곱하지 않는다 — 단, B-2 규칙으로 회당 단가를 역산해 곱했으면 그 사실(주당 횟수 포함)을 각주로 반드시 밝힌다.
- 날짜/회차 줄: 실제 수업일을 콤마로 나열하고 `(총 N강, 금액)`. 날짜는 `gen_dates.py` 결과나 `classes.json` 확정값만.
- 과목이 여러 개면 반별로 두 줄씩 반복.
- **총합계**: 모든 반 금액의 합. 할인이 있으면 `~~원래 금액~~` 취소선 + 아래에 `할인 혜택: <몇 %, 어떤 과목>` + `-> 할인 후 총액`. 일부 과목 할인이면 그 과목 소계만 할인하고 나머지는 그대로 더한다(전체 일괄 적용 금지). 할인이 없으면 취소선 없이 `총합계: 0,000원`만, 할인 줄 생략.
- **기결제**가 있으면 `- 000,000(이미 결제하신 금액)`. 없으면 이 줄을 빼고 할인 후 총액이 곧 최종 금액.
- 재계산한 반이 있으면 결과 하단에 각주(※)를 반드시 붙인다(어떤 반을 며칠부터, 정액제를 어떤 기준으로 환산했는지).
- 마지막은 항상 `■ 최종 결제 금액` 다음 줄 `= 000,000원`.
- 할인 적용 후 반올림/절사 여부가 애매하면 사용자에게 확인한다.

## 전달 전 최종 점검 (두 모드 공통)
- [ ] 0단계에서 정한 모드의 형식·할인 기본값을 지켰다 (A: 요청 없으면 할인 없음 / B: 할인·기결제를 물어봤다)
- [ ] (A) 대화·캡처에 나온 이월금·리뷰 차감을 빠뜨리지 않았고, 과목/사유별로 나눴다
- [ ] (B) 반별 회차 × 단가(또는 정액/역산 단가) 합 = 총합계, 할인 후 금액·최종 금액이 맞다
- [ ] 재계산·역산한 곳에 각주를 달았다
- [ ] 모든 금액에 천 단위 콤마, 파이썬 등으로 재검산 완료

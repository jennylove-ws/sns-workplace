# 대치SNT학원 결석·휴강·공식일정 → 구글 캘린더 자동 기록

Jenny님이 대화 중에 학생 결석, 선생님 휴강/보강, 학원 공식 일정을 언급하면 즉시 구글 캘린더에 기록한다. "캘린더에 넣어줘"라고 하지 않아도 행정팀이 같이 알아야 하는 사실이 나오면 **먼저 묻지 말고 바로 기록**하고, 기록한 뒤 **한 줄로 확인**해준다.

## 0. 시작 전 반드시 확인

1. **Google Calendar 연동 확인** — `mcp__Google_Calendar__*` 도구가 있는지. 없으면 "지금 이 창에는 Google Calendar 연동이 안 되어 있어서 자동으로 등록은 못 하고, 대화로만 도와드릴 수 있어요"라고 알린다.
2. **대상 캘린더는 항상 기본 캘린더 `ggyo.ganga@gmail.com`** — 2026-08-22 Jenny님이 "행정팀과 공유하는 학원 공식 일정 캘린더가 맞다"고 확인. 새 캘린더를 만들지 않고, `list_calendars`에 다른 캘린더가 보여도 이걸 쓴다.
3. **이 스킬 대상인지 확인 — daechi-snt-tasks와 구분한다.**

   | 내용 | 가는 곳 |
   |---|---|
   | 학생 결석 / 선생님 휴강·보강 / 학원 공식 일정(설명회, 방학, 시험기간, 개강·휴원) | **이 스킬** (구글 캘린더, 행정팀과 공유) |
   | 원장님 개인 업무(전화, 문자 발송, 결제, 구매/준비) | **daechi-snt-tasks** (Notion, 원장님 전용) |
   | 한 문장에 둘 다 (예: "OO 학생 결석 확인했고, 어머니께 전화하기") | 결석은 이 스킬로 캘린더에, "전화하기"는 daechi-snt-tasks로 Notion에 **나눠서** |

4. **날짜/요일은 절대 암산하지 않는다.** 오늘 날짜 기준으로 "다음 주 화요일", "이번 주 토요일"을 정확히 환산한다. 애매하면 날짜를 확인한다.
5. **등록 전에 같은 날짜 근처 이벤트를 조회**해서 중복이면 다시 만들지 않는다.
6. **기록 후 한 줄 확인** — 예) "구글 캘린더에 등록했어요: [결석] 김민제 (신영준T 화목반) — 8/25". 잘못됐다고 하면 그 자리에서 삭제/수정한다.

## 1. 이벤트 종류별 작성 규칙

| 종류 | 제목 형식 | 시간 |
|---|---|---|
| 학생 결석 | `[결석] 학생이름 (반명/선생님T)` | 종일(allDay). 사유를 들었으면 description에 |
| 선생님 휴강 | `[휴강] 선생님T 반명 — 사유` | 원래 수업 시간대(모르면 종일) |
| 보강 | `[보강] 학생/반명 — 원래 수업일 → 보강일` | 실제 보강 일시 |
| 학원 공식 일정 | 일정명 그대로 (예: "중3 설명회", "추석 휴원") | 하루짜리면 종일, 기간이 있으면 시작~종료 |

- 결석/휴강/보강은 관련 선생님·반명을 제목에 넣어서 캘린더만 봐도 누구 관련인지 알게 한다.
- **참석자(attendees) 초대는 하지 않는다** — 기록만. 사용자가 명시적으로 누구를 초대해달라고 할 때만 추가.
- description에는 원본 대화의 배경 정보(사유, 연락처 등)를 간단히 남긴다.

## 2. 다른 스킬과의 경계
- 회차·수강료·강의실 배정 자체를 바꾸는 일(반 전체 일정 변경)은 **tuition-schedule**. 이 스킬은 그 결과로 생긴 "이 날은 결석/휴강/보강"이라는 개별 사실만 캘린더에 남긴다. 반 전체 스케줄을 다시 짜야 하면 tuition-schedule로 먼저 넘어간다.
- 개인 할일(전화, 문자, 결제 등)은 **daechi-snt-tasks**의 Notion 할일/업무캘린더로 간다.
